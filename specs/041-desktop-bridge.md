## Context

The desktop client links the core as a Rust crate, with no wasm (`docs/spec.md` §9). Its web view is a browser, the least trusted part of the process, so it holds no key, no socket and no file (typescript-svelte skill). This spec defines everything on the Rust side of the Tauri process:

- the separate Cargo workspace it lives in (ADR 0039);
- the commands and events that are all the web view can reach, with their types generated for TypeScript;
- the web view's hardening;
- the connection host, which opens the TLS and SOCKS5 sockets, drives `Device` as spec 027-core-api R11 and R12 require, and reconnects with backoff;
- the storage key in the operating system's keychain;
- the test that closes phase 4 on the desktop side: the app with no UI opens a channel against a real server.

The human reviewer decided on 2026-09-26 that all of this belongs here and not in spec 050-desktop-mvp, which is left with the Svelte UI alone (`docs/audit-log.md`, "Phase 4 drafts", Q3).

**In plain words.** On the desktop, the app is two parts in one process: a web page that draws the screens, and Rust code that does everything else. The web page can only ask for things by name ("send this text in this channel"). It never sees a key or a socket, and it can load nothing from the internet. The Rust part keeps the storage key in the system keychain, opens the encrypted connections to the servers (through Tor when a proxy is set), and tells the page what happened. The phase closes when two copies of this Rust part, without any screen, exchange a message through a real server.

## Requirements

**The workspace**

- R1 `clients/desktop/src-tauri/` MUST be a Cargo workspace of its own (ADR 0039), with a committed `Cargo.lock`, whose one crate `privatechat-desktop` depends on `privatechat-core` and `privatechat-store` by path. Its `[lints]` MUST hold the entries of the root `[workspace.lints]` with the same levels, plus `clippy::wildcard_enum_match_arm = "deny"`, and the crate MUST contain no `unsafe` block of its own. `check_s041_t01_r01_desktop_lints` in `scripts/doc_lint.py` MUST fail when an entry of the root table is missing or weaker there.
- R2 `clients/desktop/deny.toml` MUST carry every entry of the root `[bans] deny` list. An entry may differ only by added wrappers, each named with its reason in a comment: `rustls` and `ring` under `privatechat-desktop`, `tokio-rustls` and `rustls-platform-verifier` (ADR 0039); the crates that Tauri uses for its build-time asset handling, under the Tauri crates that bring them; and the session cryptography of the Linux Secret Service store, under that store's crate. `aws-lc-rs`, `aws-lc-sys`, `openssl`, `openssl-sys` and `native-tls` MUST stay banned with no wrapper. `check_s041_t02_r02_desktop_bans` in `scripts/doc_lint.py` MUST fail when an entry of the root list is missing, and `cargo deny check` in `clients/desktop/src-tauri/` MUST be green.
- R3 In the pull request that marks this spec `accepted`, AGENTS 2 MUST name the desktop TLS stack as its second exception, and `docs/spec.md` §9 MUST name it in the desktop row (ADR 0039).

**What the web view can reach**

- R4 The web view MUST reach the core only through the Tauri commands of `src-tauri/src/commands.rs`. There MUST be exactly one command for each of `unlock`, `lock`, `reset_local_data`, `status`, `acknowledge_settings`, `remove_broken`, `channels`, `create_channel`, `probe_server`, `import_qr`, `import_file`, `export_qr`, `export_file`, `rename_channel`, `leave`, `send`, `messages`, `channel_status`, `gaps`, `peers`, `label`, `verify`, `verify_scanned`, `mute`, `fingerprint`, `own_fingerprint`, `retire`, `regenerate_identity`, `own_old_keys`, `forget`, `settings`, `set_default_server_url`, `set_lock_timeout_seconds` and `set_socks5_proxy`. Each MUST call the `Device` method of the same name through the host (R10) and return its `Result`. `connections`, `probe_plan`, `on_connect`, `on_frame`, `on_tick`, `outgoing`, `on_disconnect`, `flush` and `purge_expired` MUST NOT be commands: the host alone calls them. No command takes `now`. The host reads the system clock in milliseconds since the Unix epoch, which is allowed here because this crate is not `core` (AGENTS 10).
- R5 The argument and result types MUST be generated by `tauri-specta`, at a version pinned exactly, into `clients/desktop/src/lib/bridge/generated.ts`. That file is committed, and CI MUST fail when regenerating it changes it. The types cross as follows:
  - Ids cross as lowercase hexadecimal strings: `channel_id`, `server_id` and `ClientRef` as 32 characters, `PeerId` as 64. On the TypeScript side each is a branded type (`ChannelId`, `ServerId`, `ClientRef`, `PeerId`). An incoming id that is not exactly that returns `BadLength` before any `Device` call.
  - A `u64` crosses as a TypeScript `number`, saturated at 2^53 − 1, so that a time from an untrusted server that is too large to represent keeps its order and never wraps around.
  - Errors cross as the tagged union of `Error` with `Store` carrying its reason, plus `Locked` (the device is locked), `KeyLost` and `KeychainUnavailable` (R16).
- R6 The `.chatcfg` password of `import_file` MUST reach the command as the raw IPC body (`tauri::ipc::Request` with `InvokeBody::Raw`), never as JSON. The host zeroes that body after the call. The seven-word password of `export_file`, the text of `export_qr` and the `qr` of a `Fingerprint` MUST return as a raw binary response (`tauri::ipc::Response`), never as a JSON string. The `.chatcfg` file of `import_file` and `export_file` MUST be read and written by the Rust side through the native file dialog of `tauri-plugin-dialog`, so that its bytes never enter the web view.
- R7 The host MUST emit to the web view one event, `core-event`, whose payload is the tagged union of the `Event` variants of spec 028-session-sans-io that name a channel (`Subscribed`, `HistoryTruncated`, `Message`, `Delivered`, `NotDelivered`, `StatusChanged`, `StorageFailed`, `SubscribeRefused`, `ChannelFull`), typed by R5. It MUST also emit `connection-state { channels, state }`, where `state` is `connecting`, `connected`, `retrying`, `server_full`, `unsupported_server` or `needs_proxy`, for the channels of a plan whenever their state changes, and `locked` when the device locks. `ServerFull`, `UnsupportedServer` and `Reconnect` are acted on by the host (R13) and reach the web view only as `connection-state`.
- R8 `tauri.conf.json` MUST set the content security policy `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' asset:`, with no remote origin, no `withGlobalTauri` and no developer tools in release builds. The capability file MUST grant exactly the commands of R4, listening to the events of R7, and the `open` and `save` dialogs. The one window MUST be created `incognito`, so that the web view keeps no cookie, cache or storage on disk. Its title MUST be the app name, and no command changes it (`docs/spec.md` §8 "Window and WebView").

**The connection host**

- R9 The host MUST NOT depend on the Tauri runtime: it emits through a trait `Sink` that the app implements with Tauri's `emit` and the tests with a channel, so that the exit test (R18) runs it without a window.
- R10 The host MUST hold the `Device` in a `Mutex<Option<Device>>` and run every `Device` call inside `tokio::task::spawn_blocking`. After `open` and after each call that spec 027-core-api R11 names, and before the command returns, it MUST reconcile its sockets with `connections()` and write `outgoing()` of every connected plan to its socket. There is one `tokio` task per plan `id`, and it is cancelled when its `id` leaves the plan.
- R11 While the device is unlocked, the host MUST call `on_tick(now)` every 1 000 ms on a `tokio` interval with `MissedTickBehavior::Delay`, emit the events it returns, and then reconcile and drain as R10 does.
- R12 For each plan, the task MUST open the socket along its `Route`:
  - Proxy: with `socks5_proxy` set, through the client of `src-tauri/src/socks5.rs`, which sends a SOCKS5 `CONNECT` (RFC 1928) with the host as a domain name (`ATYP` 3), so that no host name is ever resolved on this device, and offers only username and password authentication (RFC 1929), with `socks_username` and an empty password. Without a proxy, it opens a TCP connection to `host:port`.
  - TLS: when `tls` is true, TLS 1.3 only through `rustls` with the `ring` provider, `resumption` disabled, SNI set to `host`, and certificates checked by `rustls-platform-verifier`, with no pinning and no way to skip the check.
  - WebSocket: the handshake of `GET /` (spec 030-ws-protocol R3), sending exactly the headers of `docs/spec.md` §6 "Transport" with `User-Agent: privatechat/1`, no `Origin` header and no extension, with the maximum frame and message size set to 70 000 bytes. A text frame closes the socket.
  - Timeouts: from the TCP connect to the end of the WebSocket handshake, 30 000 ms. After that, 75 000 ms with no frame of any kind received (the server pings every 30 000 ms, spec 033-rate-limit-quotas R4) closes the socket.
  - Once open, it calls `on_connect(id, now)`, passes every binary frame to `on_frame`, and calls `on_disconnect(id)` when the socket closes, whoever closed it.
- R13 A socket that the network or the server closed MUST be reopened while its `id` is in the plan, after 1 000 ms, then 2 000 ms, doubling up to 60 000 ms. The delay resets once a connection has stayed open for 60 000 ms. After `Event::UnsupportedServer`, the host MUST close that socket and not reopen it until the next `unlock` or a new plan `id`. After `Event::Reconnect`, it MUST close the socket and reopen it with the backoff (spec 027-core-api R11).
- R14 `probe_server(url)` MUST call `probe_plan(url)`, and return `NotYet` for `None` and the error for `Err`. Otherwise it MUST open a socket along the route as R12 does, pass the first binary frame to `probe_hello`, and close the socket. The result is `Supported` or `Unsupported` from `probe_hello`, and `Unreachable` when the socket fails or no frame arrives within 30 000 ms (spec 027-core-api R12).

**The storage key and the lock**

- R15 The data directory MUST be `app_local_data_dir()/data`: Application Support on macOS, `%LOCALAPPDATA%` on Windows (never the roaming profile, which syncs), `$XDG_DATA_HOME` on Linux. It is created with mode 0700 on Unix and is separate from anything the web view uses (`docs/spec.md` §8 "Backup exclusion").
- R16 The storage key MUST live in the operating system's keychain through `keyring` 4, with the native store of each system (the macOS Keychain, the Windows Credential Manager, the Secret Service over D-Bus on Linux), under one entry whose service is the app identifier constant and whose user is `storage-key`, holding 32 bytes read and written with `get_secret` and `set_secret`. `unlock` MUST behave as follows:
  - The entry reads as 32 bytes: copy them into a `[u8; 32]`, zero the vector, build the key with `StorageKey::from_bytes`, and open the device with `DataDir::open` and `Device::open`.
  - There is no entry and the data directory holds no file: draw a new key with `generate_storage_key` (spec 040-uniffi R8), write it, read it back, and open.
  - There is no entry but the directory holds files, or the entry is not 32 bytes: return `KeyLost` and create nothing. No transient failure may ever draw a new key (`docs/spec.md` §8 "Loss of the wrapping key").
  - Any other keychain error: return `KeychainUnavailable` and create nothing.
  `reset_local_data`, which the UI offers only behind a destructive confirmation, MUST delete the data directory and the entry. The next `unlock` then starts as a fresh install. The key never leaves the Rust side.
- R17 `lock` MUST close every socket (calling `on_disconnect` for each), call `Device::flush(now)`, drop the `Device` whatever `flush` returned, stop the tick, and emit `locked`. After that, every command other than `unlock`, `reset_local_data` and `lock` returns `Locked`. Closing the window or quitting the app MUST lock first. When the device locks on its own (session lock, timeout) is spec 053-device-security's.

**The exit test**

- R18 `clients/desktop/src-tauri/tests/phase4_exit.rs` MUST run two hosts, each over its own temporary data directory and an in-memory keychain store, against the `privatechat-server` binary of spec 035-server-ops started with its onion listener on `127.0.0.1` and the onion host of the test in its host names. A SOCKS5 proxy written for the test on `127.0.0.1` forwards every `CONNECT` for that host to the onion listener. Both hosts set `127.0.0.1:<proxy port>` as their SOCKS5 proxy. Host A creates a channel with `ws://<56 characters>.onion`, exports its QR, and host B imports it. Each sends one message. The test MUST end with each host having received the other's message as `core-event` `Message` and its own as `Delivered`, and with the proxy having seen a different `socks_username` for each plan. The CI job `desktop` MUST build the server from the root workspace and run this test, together with `cargo test`, clippy, rustfmt and `cargo deny check` in `clients/desktop/src-tauri/`.

## Limits

| Input | Range | Out of range |
| --- | --- | --- |
| Ids from the web view | exactly 32 or 64 lowercase hex characters | `BadLength`, no `Device` call |
| `u64` to the web view | 0..=2^53 − 1 | saturated at 2^53 − 1 |
| Connect and handshake | ≤ 30 000 ms | socket closed, backoff |
| Silence on an open socket | ≤ 75 000 ms | socket closed, backoff |
| Backoff | 1 000 ms doubling to 60 000 ms, reset after 60 000 ms connected | — |
| Probe's first frame | ≤ 30 000 ms | `Unreachable` |
| Tick | every 1 000 ms while unlocked | delayed, never burst |
| WebSocket frame and message | ≤ 70 000 B | socket closed |
| Keychain secret | exactly 32 bytes | `KeyLost` |
| SOCKS5 username | the 8 characters of the plan; password empty | — |

## Security

- The web view holds no key, no socket, no file and no `.chatcfg` bytes (R4, R6). What reaches it is what the user reads: message text, names, fingerprints, and the export password while it is on screen, as bytes that the page zeroes when it goes away (typescript-svelte skill). A script injected into the page could read the open channels' messages and send in them, but not take the storage key, the channel key or any identity key out of the process. The CSP and the capability list (R8) are what keep such a script out.
- Every host name is resolved by the proxy when one is set (R12), and one plan is one proxy username, so Tor gives one circuit per plan (spec 027-core-api R10). Plain WebSocket runs only to a `.onion` host through a loopback proxy, which is spec 027-core-api R10's rule and not repeated here.
- TLS is 1.3 only, with no resumption and no ticket, and certificates are checked by the operating system's verifier (R12, ADR 0039). A flaw in the TLS stack exposes the transport, never a message (`docs/spec.md` §4).
- The key goes from the keychain into `StorageKey` through a zeroed array (R16), never into the web view or a log. Within the user's session, any process of that user can read the keychain entry and the files. `docs/spec.md` §8 documents this, and it is not changed here.
- No transient keychain failure draws a new key (R16), so a keychain that is briefly unavailable never makes the app write a new key over data it can no longer read.
- The saturation of R5 cannot change the order a message is shown in, since the core delivers the order (architecture skill §7). It only keeps an absurd server time from wrapping around in the page.

- T02 (covers R2): `check_s041_t02_r02_desktop_bans`: a desktop `deny.toml` missing `sha1` fails; the real file passes; `cargo deny check` green; `cargo tree -i aws-lc-rs` and `cargo tree -i openssl-sys` find nothing.
- T03 (covers R3): `check_s041_t03_r03_agents_names_desktop_tls`, once this spec is `accepted`: AGENTS 2 and §9 name ADR 0039.
- T04 (covers R4): `s041_t04_r04_command_list`: the handler list registered with Tauri equals the list of R4, and no command signature carries `now`.
- T05 (covers R5): `s041_t05_r05_types`: a 31-character or uppercase channel id → `BadLength` with nothing committed; a `Received` with `received_at` 2^60 crosses as 2^53 − 1; CI step `s041_t05_r05_generated_ts_current`: regenerating `generated.ts` leaves `git diff` empty.
- T06 (covers R6): `s041_t06_r06_raw_bodies`: `import_file` with a wrong password as a raw body → `BadPassword`, and the body buffer is zeros afterwards; the `export_file` response is binary, not JSON.
- T07 (covers R7): `s041_t07_r07_events`: a `Message` from `on_frame` reaches the `Sink` as `core-event`; an `UnsupportedServer` reaches it only as `connection-state` `unsupported_server`; `lock` emits `locked`.
- T08 (covers R8): `s041_t08_r08_webview_config`: `tauri.conf.json` has exactly the CSP of R8, `withGlobalTauri` absent and the window `incognito`; the capability file grants exactly the commands of R4 and the two dialogs.
- T09 (covers R9): `s041_t09_r09_host_without_tauri`: `Host` is built and unlocked in a plain `tokio` test with a channel `Sink`.
- T10 (covers R10): `s041_t10_r10_reconcile`: after `create_channel` a socket task exists for the new plan `id`, and after `leave` of its only channel it is cancelled; a `send` puts its `publish` on the socket before the command returns; a call runs on a blocking thread, not on the runtime's worker.
- T11 (covers R11): `s041_t11_r11_tick`: with a paused `tokio` clock, 5 000 ms of time give 5 calls of `on_tick`, and a 4 000 ms stall gives one delayed tick, not a burst.
- T12 (covers R12): `s041_t12_r12_socket`: against a test SOCKS5 server, the `CONNECT` carries `ATYP` 3 with the host name and the plan's username with an empty password, and no DNS query is made; against a local TLS server with a test root (a `cfg(test)` constructor of the client configuration), TLS 1.2 is refused, and a second connection makes a full handshake with no ticket and no PSK; the WebSocket request carries exactly the headers of §6 and no `Origin`; a 70 001-byte frame closes the socket; a text frame closes it; 75 000 ms of silence closes it.
- T13 (covers R13): `s041_t13_r13_backoff`: with a paused clock, the reopen delays are 1 000, 2 000, 4 000 … 60 000, 60 000 ms, and reset after 60 000 ms connected; after `UnsupportedServer` no reopen happens until a new `unlock`; after `Reconnect` a reopen follows the backoff.
- T14 (covers R14): `s041_t14_r14_probe`: a server that sends `hello` with version 1 → `Supported`; one with versions 2 and 3 → `Unsupported`; one that sends nothing → `Unreachable` after 30 000 ms; while `settings_reset` → `NotYet`; a URL with a path → `BadConfig`.
- T15 (covers R15): `s041_t15_r15_data_dir`: on Unix the directory is created with mode 0700; on Windows the path is under `%LOCALAPPDATA%`.
- T16 (covers R16): `s041_t16_r16_unlock`, over the in-memory `KeyStore`: first run → a key written and the device open; second run → the same key; entry deleted with files present → `KeyLost` and nothing written; a 31-byte entry → `KeyLost`; a keychain error → `KeychainUnavailable` and nothing written; `reset_local_data` then `unlock` → a new key and an empty device.
- T17 (covers R17): `s041_t17_r17_lock`: after `lock`, `channels` → `Locked`; the tick stops; each open socket got `on_disconnect`; a failing `flush` still drops the device.
- T18 (covers R18): `s041_t18_r18_phase4_exit`: the run of R18.

## Vectors

None. The bridge calls `Device` in-process, in Rust, so every vector already reaches it through `cargo test` in the root workspace. The boundary to check is the IPC one, which T05 and T06 cover.

## Acceptance criterion

`cargo test` in `clients/desktop/src-tauri/` green, T18 included; the CI job `desktop` green; the documentation lint green. With spec 040-uniffi green as well, phase 4 closes (`docs/spec.md` §10).
