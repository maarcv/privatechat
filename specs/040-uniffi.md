## Context

The Android and iOS clients reach the core through uniffi (`docs/spec.md` §9, ADR 0012). Spec 027-core-api fixed the boundary as one opaque handle, `Device` (ADR 0037), whose calls name channels and connections by id. This spec wraps that handle for Kotlin and Swift and nothing else. It covers the Rust crate that exports it, how each Rust type crosses the boundary, how secrets cross, the thread every call runs on, how the platform libraries are built, and the test that closes phase 4 on the mobile side (`docs/spec.md` §10).

The cryptography exists once, in Rust. What can still differ on a phone is the boundary: bytes, 64-bit numbers, optional fields and error variants must reach Kotlin and Swift unchanged. The vector test of this spec therefore drives the real `Device` from Kotlin and Swift with every vector that can reach it, decided with the human reviewer on 2026-09-26 (`docs/audit-log.md`, "Phase 4 drafts", Q1). The vectors of crate-internal functions stay with `cargo test`, which runs the same code. During audit L the reviewer raised the iOS floor to 17, which the Swift layer's executor needs (`docs/audit-log.md`, "Audit L", L-Q5).

**In plain words.** A small Rust crate turns `Device` into a Kotlin class and a Swift class, generated by uniffi. A thin hand-written layer on top runs every call on one background thread shared by the whole app, in order, so a slow call (opening an invitation file costs about a second) never freezes the screen, and closing and reopening the device can never overtake each other. That layer also wipes the password, the invitation text and the storage key from the app's memory right after handing them over. The apps use only that layer to call the device. Tests in Kotlin and Swift load the same vector files as Rust and check that importing invitations, reading fingerprints and recognising a server's greeting give exactly the same results on each platform.

## Requirements

**The crate**

- R1 The crate `privatechat-ffi` MUST live in `bindings/uniffi/`, be a member of the root workspace with `[lints] workspace = true` and `crate-type = ["cdylib", "staticlib", "lib"]`, and depend on exactly `privatechat-core`, `privatechat-store`, `uniffi` `=0.32.2` with `default-features = false`, and `zeroize`; its dev-dependencies are `privatechat-core` with its `test-support` feature (spec 020-store-files, which holds the `FailingVault`) and `privatechat-store`. It MUST contain no `unsafe` block of its own: the scaffolding that uniffi's macros generate is the only unsafe code in it (measured on 2026-09-26: the root workspace lints raise nothing on it). The code generator MUST be a separate crate, `privatechat-uniffi-bindgen` in `bindings/uniffi/bindgen/` (`publish = false`), the only crate that enables uniffi's `cli` feature, and it MUST be a workspace of its own with a committed `Cargo.lock`, listed in the root `exclude`, so that no build of the root workspace unifies `cli` into the library the apps ship (measured: `cli` brings in `log`, and a `--workspace` build with both crates as members links it). Like the fuzz crate of spec 016-fuzz-harness, it runs no `cargo deny` step of its own: it builds nothing that ships. `cargo deny --all-features check` MUST stay green with no new entry. uniffi's runtime depends on `uniffi_pipeline`, which depends on `tempfile`, and so on `fastrand` and `getrandom`; the library calls none of them and links none (measured with `nm`), and the comment of `deny.toml` on the `tempfile` wrapper MUST name that path.
- R2 The crate MUST export with proc macros only (no UDL, `docs/spec.md` §9). It MUST export exactly the object `FfiDevice`; the free functions `core_init` (which calls `core::init`), `probe_hello`, `default_server_url` and `generate_storage_key`; one uniffi `Record` for each struct and one uniffi `Enum` for each enum that spec 027-core-api's Interface lists as `pub` for the bindings, except `ClientRef` and `PeerId`, which cross by R3, `AckOutcome` and `Frame`, which stay inside the core, and `Error` and `StoreError`, which R4 maps, with the same name prefixed `Ffi`, the same fields and variants in the same order, types translated by R3; and `FfiError` and `FfiStoreError` (R4). `bindings/uniffi/tests/api_surface.rs` MUST coerce every exported function and method to a function pointer of its exact type, as spec 027-core-api R16 does for `core`.
- R3 Every `[u8; N]` of the core boundary (`channel_id`, `server_id`, `ClientRef`, `PeerId`, the QR and fingerprint bytes) MUST cross as `Vec<u8>` in both directions. An incoming vector of the wrong length MUST return `FfiError::BadLength` before any `Device` call. `u64` and `u32` MUST cross as uniffi's unsigned types (Kotlin `ULong` and `UInt`, Swift `UInt64` and `UInt32`), `&str` and `String` as `String`, `&[u8]` and `Vec<u8>` as `Vec<u8>` (Kotlin `ByteArray`, Swift `Data`), and `Option<T>` as an optional. Each conversion MUST be written once, as a `From` or `TryFrom` impl in `bindings/uniffi/src/convert.rs`, with an exhaustive `match`. The crate MUST deny `clippy::wildcard_enum_match_arm` and `clippy::match_wildcard_for_single_variants`, so that no `_` arm can hide a variant added to the core, which then fails to compile here.
- R4 `FfiError` MUST have the variants of `core::Error` (spec 027-core-api R18) in the same order, `Store(StoreError)` becoming `Store { reason: FfiStoreError }` with the six variants of `StoreError` (spec 020-store-files R26), followed by one variant of its own, `Closed` (R6). Its `Display`, which uniffi requires, MUST write the variant name and nothing else. The messages that the generated Kotlin and Swift code builds come from the fields, and none carries data. Every exported function and method, and `FfiDevice`'s `Drop`, MUST run its body through one helper of `lib.rs` that catches a panic with `catch_unwind` and returns `FfiError::Internal` (or, in `Drop`, nothing), so that no panic message crosses the boundary. The same helper MUST install, through a `std::sync::Once`, a panic hook that writes nothing, before its first body runs. The clients map errors by variant and never show the message.

**The handle**

- R5 `FfiDevice` MUST hold a `Mutex<Option<Device>>`. Its constructor `open(data_dir, storage_key, now)` MUST return `FfiError::BadLength` for a `storage_key` that is not 32 bytes long. Otherwise it MUST copy the key into a `[u8; 32]`, build the key with `StorageKey::from_bytes` (which zeroes that array), and call `DataDir::open(path, key)` and then `Device::open` with that directory as its vault, mapping every error by R4 (`Store { reason: Locked }` when another holder has the `LOCK` file). A `cfg(test)` constructor over a `Box<dyn Vault>` lets the tests use the `FailingVault` of spec 020-store-files. Each method of `Device` in spec 027-core-api's Interface MUST be a method of `FfiDevice` with the same name and the arguments of R3. Each method takes `&self` and holds the lock for the whole call. `open` MUST zero the incoming `storage_key` vector on every path.
- R6 `close(now)` MUST call `Device::flush(now)`, drop the `Device` whatever `flush` returned, and return `flush`'s result. Dropping the `Device` closes its files, releases the `LOCK` and zeroes `K_db` (spec 027-core-api R24). After `close`, every method MUST return `FfiError::Closed` and `close` again MUST return `Ok`. A lock poisoned by an earlier panic MUST make every later call return `FfiError::Internal`, except `close` and `Drop`, which recover the lock to drop the `Device` without `flush`, so that the state of a call that panicked half-way is not written, and clear the poison; `close` then returns `Internal`, and every later call `Closed`.
- R7 `import_file` MUST zero its `password` vector, and `import_qr` its `text` vector (the invitation text holds `K_ch`, spec 011-config-format), before returning, on every path. `export_file` MUST return an `FfiExportedFile { file, password }` whose password is bytes, and `export_qr` returns its text as bytes. No exported function MUST take or return a key, a seed, a password or an invitation text as `String` (spec 027-core-api R19).
- R8 `generate_storage_key()` MUST return 32 bytes drawn through the core. This spec amends spec 027-core-api by adding `pub fn generate_storage_key(out: &mut [u8; 32]) -> Result<(), Error>`, which fills the caller's array with libsodium's `randombytes_buf`. With it, all three platforms draw `K_db` from the one randomness source of AGENTS 2, and the desktop bridge (spec 041-desktop-bridge) has a source it may use. Outside `core::crypto`, a key exists as a plain `[u8; 32]` only in an array that its caller owns and zeroes: the one given to `generate_storage_key` and the one given to `StorageKey::from_bytes`, in this crate, in spec 041-desktop-bridge and in spec 020-store-files.

**The platform layer**

- R9 `bindings/uniffi/kotlin/` MUST hold a Gradle library whose package `org.privatechat.core` provides `class Core`, and `bindings/uniffi/swift/` a Swift package `PrivatechatCore`, for iOS 17 and macOS 14 or later, that provides `public final class Core`. Each process has exactly one serial executor, shared by every `Core` instance and by the free functions:
  - in Kotlin, one single-thread dispatcher held by the companion object, never closed. Every call runs in `withContext(NonCancellable) { withContext(dispatcher) { … } }`: the inner switch resumes into a non-cancellable context, so that a caller cancelled during the call still receives its result, and the events or frames of a call that already ran are never lost (a single `withContext(NonCancellable + dispatcher)` discards the result on return to a cancelled caller; measured on 2026-09-26). A caller already cancelled before the call still runs it;
  - in Swift, one `DispatchSerialQueue`, which is the `unownedExecutor` of a `@globalActor actor CoreActor`. `Core`, its static `open`, and the twin of each free function are isolated to `CoreActor`.
  Every call of `FfiDevice` and of a free function runs on that executor, one at a time. Calls made in sequence, or from one actor or one single-threaded dispatcher (the main thread, `CoreActor`), run in the order they were made, so that an `open` made after a `close` always runs after it; calls from unrelated tasks reach the executor in whatever order they are scheduled (measured on 2026-09-26), so an `open` is ordered after a `close` only when its caller awaited that `close`. Spec 053-device-security serialises the app's lock and unlock as spec 041-desktop-bridge R15 does, each `open` awaiting the last `close`. `Core` has one `suspend` (Kotlin) or `async throws` (Swift) method per method of `FfiDevice` and per free function other than `core_init`, which `Core` calls once, itself, before its first call. `Core.open(dataDir, storageKey, now)`, `importFile(bytes, password, …)` and `importQr(text, …)` MUST overwrite the key, password or text they were given with zeros after the call, on every path: Kotlin with `fill(0)` on the `ByteArray` in a `finally`, Swift with `resetBytes` on the `inout Data` in a `defer`. `generateStorageKey()` returns the new key, which the caller hands to spec 053-device-security and zeroes. `close` MUST NOT close the executor: calls after it reach `FfiDevice` and return `Closed`.
- R10 No source file under `clients/android/` or `clients/ios/` MUST name `FfiDevice` or one of the generated free functions (`coreInit`, `probeHello`, `defaultServerUrl`, `generateStorageKey`). A match is a whole identifier equal to one of those names (so `FfiDeviceStatus` passes) that is qualified by the generated module (`uniffi.privatechat_ffi.`, `privatechat_ffi.`) or not qualified at all; a call qualified by `Core.` is the twin and passes. The apps call the core through `Core` alone, and use the generated records, enums and errors directly (Kotlin names the error class `FfiException`). `scripts/check_bindings_use.sh` MUST enforce this in CI by name, not by import, so that a fully qualified reference is caught too. Every `Device` call therefore runs off the UI thread (ADR 0037), and calls to one device never interleave.
- R11 `scripts/build_bindings.sh` MUST take one argument, `host`, `android` or `ios`, and build the library with `cargo build -p privatechat-ffi --release`, never `--workspace`, then generate the sources with `privatechat-uniffi-bindgen generate --library`: the Kotlin sources into `target/uniffi/kotlin/`, and the Swift sources and the XCFramework into `bindings/uniffi/swift/Generated/`, inside the package, since SwiftPM refuses a path outside it. The generated sources MUST NOT be committed (AGENTS 16): `.gitignore` MUST list `bindings/uniffi/swift/Generated/`, `bindings/uniffi/bindgen/target/`, Gradle's `build/` and `.gradle/`, and SwiftPM's `.build/`, and `bindings/uniffi/README.md` MUST describe this layout. `android` MUST build the `.so` for `arm64-v8a`, `armeabi-v7a` and `x86_64` at API level 26 with `cargo ndk` and the NDK version pinned in the script. `ios` MUST build an XCFramework from `aarch64-apple-ios`, `aarch64-apple-ios-sim` and `aarch64-apple-darwin`, the last for `swift test` on the macOS runner. `host` MUST build the library that the Kotlin tests load on the JVM. libsodium MUST be built from the archive that `libsodium-sys-stable` pins, for every target: the script MUST unset `SODIUM_LIB_DIR`, `SODIUM_USE_PKG_CONFIG` and `SODIUM_SHARED` and fail when one is still set, so that no platform links a libsodium other than the one that was audited (spec 010-primitives-wrapper, "Bumping libsodium").
- R12 A CI job `bindings` MUST run on a macOS runner. It MUST run `scripts/build_bindings.sh` for all three arguments; in `bindings/uniffi/kotlin/`, `./gradlew test ktlintCheck detekt` with the JDK and the Gradle wrapper pinned there; in `bindings/uniffi/swift/`, `swift test`, SwiftLint and SwiftFormat as the swift skill sets them up; and `scripts/check_bindings_use.sh`. `.github/CONTRIBUTING.md` MUST list the same commands (AGENTS 17). ## Security

- Secrets cross by value in six places: the storage key out of `generate_storage_key` and into `open`, the `.chatcfg` password into `import_file`, the seven-word password out of `export_file` (ADR 0028), and the invitation text, which holds `K_ch`, into `import_qr` and out of `export_qr`. Rust zeroes what it receives (R5, R7), and `Core` zeroes the array the app gave it (R9). These copies are not zeroed: the buffers that uniffi's generated code allocates between the platform array and the Rust vector; the vectors that `generate_storage_key`, `export_file` and `export_qr` return, freed until the allocator reuses them; and the copies Swift makes of a `Data` it passes on (zeroing a shared buffer copies it first). The QR that spec 054-qr-invite draws from the exported text is the app's. This matches `docs/spec.md` §8 "FFI boundary": outside the core, non-retention is promised, not erasure. These are documented residuals.
- `Config`, `Channel`, `Session` and the stores never cross. The handle is opaque (ADR 0037), and the records that come out carry no key, except the password, which crosses as the byte field `password` of `FfiExportedFile`, and the invitation text, which crosses as a bare byte vector.
- `FfiError` carries no data, no panic message crosses, the panic hook writes nothing from the first call on (R4), and the crate emits no log and links no logging crate (R1), so nothing of a message, a key or a path reaches `logcat`, the unified log or a crash report through the bindings.
- A wrong-length id returns an error before the core is called (R3). An id of the right length that names no open channel is the core's `UnknownChannel`.
- `Core` serialises every call of the process on one executor (R9, R10). The socket loop of each app therefore cannot interleave an `on_frame` with a `send` of the same device, and the one-writer rule of spec 027-core-api holds without the app knowing it. A one-second `import_file` delays frame processing by that second, well inside the 5 000 ms gap of spec 028-session-sans-io R9; the platform socket answers the server's pings on its own.
- Every platform builds libsodium from the pinned, signature-checked archive (R11), so the phones run the same library that the Rust vectors of spec 010-primitives-wrapper checked.

## Public API changes

One function is added to the core: `generate_storage_key(out: &mut [u8; 32]) -> Result<(), Error>` (R8), listed in spec 027-core-api's Interface and its `api_surface.rs`. Nothing else changes. The bindings wrap spec 027-core-api as it stands.

## Vectors

None of its own. It checks through the bindings the vectors of specs 011-config-format, 014-fingerprint and 028-session-sans-io that reach `Device` (R13), after the amendments of R14. The vectors of specs 010, 012, 013, 017 and 031 test crate-internal functions: `cargo test` checks them on the same code, and no platform call reaches them on its own.

## Acceptance criterion

`cargo test -p privatechat-ffi s040_`, `./gradlew test` in `bindings/uniffi/kotlin/` and `swift test` in `bindings/uniffi/swift/` green; the CI job `bindings` green, with the Android and iOS builds. With spec 041-desktop-bridge accepted and green as well, phase 4 closes. Non-automatable: a second person reads `Core` in both languages next to spec 027-core-api's Interface and confirms that every method is there, that none is called from the caller's thread, and that every byte array holding a secret is zeroed.

## Out of scope

- Where the storage key comes from and how it is wrapped: Keystore, Secure Enclave and the lock timeout (spec 053-device-security).
- The sockets, TLS, SOCKS5, backoff and the one-second tick on Android and iOS (specs 051-android-mvp, 052-ios-mvp).
- Running the libraries on a device or an emulator; the first on-device run is in phase 5.
- Publishing the AAR or the Swift package anywhere; the apps build them from the repository.
- The desktop client, which links the core as a Rust crate (spec 041-desktop-bridge).
