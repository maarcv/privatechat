## Context

The Android and iOS clients reach the core through uniffi (`docs/spec.md` §9, ADR 0012). Spec 027-core-api fixed the boundary as one opaque handle, `Device` (ADR 0037). Since ADR 0041, the `Device` lives inside the connection host of spec 042-connection-host, which also opens every server connection, ticks the device and reconnects, for the three clients. So what crosses to Kotlin and Swift is the host, not the bare `Device`: the phones call it by name, as the desktop's web view calls its commands, and receive back, through a callback they implement, what happened. This spec covers the Rust crate that exports it, how each Rust type crosses the boundary, how secrets cross, how the platform libraries are built, and the tests that close phase 4 on the mobile side (`docs/spec.md` §10).

The cryptography exists once, in Rust. What can still differ on a phone is the boundary: bytes, 64-bit numbers, optional fields and error variants must reach Kotlin and Swift unchanged. The vector test of this spec therefore drives the real host from Kotlin and Swift with every vector that can reach it, decided with the human reviewer on 2026-09-26 (`docs/audit-log.md`, "Phase 4 drafts", Q1). The vectors of crate-internal functions stay with `cargo test`, which runs the same code. During audit L the reviewer raised the iOS floor to 17 (`docs/audit-log.md`, "Audit L", L-Q5), and while drafting phase 5 the reviewer moved the phones' sockets into the shared host ("Phase 5 drafts", Q8).

**In plain words.** A small Rust crate turns the shared host into a Kotlin class and a Swift class, generated by uniffi. Every call is asynchronous, so the screen never waits on the core, and the host itself keeps the calls in order. The app gives the host a listener, and the host tells it through that listener when a message arrives, when a message was delivered, when a connection changes state and when the device locked. A thin hand-written layer on top wipes the password, the invitation text and the storage key from the app's memory right after handing them over, and the apps use only that layer. Tests in Kotlin and Swift load the same vector files as Rust and check that importing invitations, reading fingerprints and recognising a server's greeting give exactly the same results on each platform; a second test sends one message through a real server from each language.

## Requirements

**The crate**

- R1 The crate `privatechat-ffi` MUST live in `bindings/uniffi/`, a Cargo workspace of its own (ADR 0041) listed in the root `exclude`, with a committed `Cargo.lock`, `crate-type = ["cdylib", "staticlib", "lib"]`, and depend on exactly `privatechat-core`, `privatechat-store` and `privatechat-host` by path, `uniffi` `=0.32.2` with `default-features = false` and the feature `tokio` (which the async exports of R2 need, measured on 2026-09-27), `tokio`, `futures-util` and `zeroize`; its dev-dependencies are `privatechat-core` with its `test-support` feature (spec 020-store-files) and `privatechat-host` with its own (spec 042-connection-host R1). Its lints, release profile, libsodium pin and `clippy.toml` MUST follow spec 042-connection-host R1, whose check covers this workspace. It MUST contain no `unsafe` block of its own: the scaffolding that uniffi's macros generate is the only unsafe code in it (measured on 2026-09-26: the root workspace lints raise nothing on it). `bindings/uniffi/deny.toml` MUST start from `crates/host/deny.toml` and differ from it only by narrowing `[graph] targets` to `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android`, `aarch64-apple-ios`, `aarch64-apple-ios-sim`, `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu` (the last two for the tests of R12), and by the `[bans] allow` list of spec 053-device-security R16; the check of spec 042-connection-host R2 applies to it. uniffi's runtime depends on `uniffi_pipeline`, which depends on `tempfile`, and so on `fastrand` and `getrandom`; the library calls none of them and links none (measured with `nm`), and the comment of that file on the `tempfile` wrapper MUST name that path. The code generator MUST be a separate crate, `privatechat-uniffi-bindgen` in `bindings/uniffi/bindgen/` (`publish = false`), the only crate that enables uniffi's `cli` feature, and it MUST be a workspace of its own with a committed `Cargo.lock`, listed in the `exclude` of `bindings/uniffi/Cargo.toml`, so that no build unifies `cli` and its command-line dependencies into the library the apps ship. Like the fuzz crate of spec 016-fuzz-harness, it runs no `cargo deny` step of its own: it builds nothing that ships.
- R2 The crate MUST export with proc macros only (no UDL, `docs/spec.md` §9). It MUST export exactly:
  - the object `FfiHost` (R5);
  - the foreign trait `FfiSink` (`#[uniffi::export(with_foreign)]`), which the platform implements, with the methods of spec 042-connection-host's `Sink` other than `before_connect`, which the adapter answers (R6);
  - the free functions `core_init` (which calls `core::init`), `probe_hello`, `default_server_url` and `generate_storage_key`;
  - one uniffi `Record` for each struct and one uniffi `Enum` for each enum that a method of `FfiHost` takes or returns: those of spec 027-core-api's Interface that are `pub` for the bindings, except `ClientRef` and `PeerId`, which cross by R3, `AckOutcome`, `Frame`, `ConnectionPlan`, `Route` and `Event`, which no exported method reaches, and `Error` and `StoreError`, which R4 maps; and those of spec 042-connection-host that cross: `SentView`, `HostEvent`, `ConnectionState` and `ProbeResult`. Each has the same name prefixed `Ffi`, the same fields and variants in the same order, types translated by R3;
  - `FfiError` and `FfiStoreError` (R4).
  Every method of `FfiHost` other than `new`, `with_fixed_clock` and `network_changed` MUST be an `async fn` exported with `async_runtime = "tokio"`, whose body runs on the host's own runtime (R5), so that no call blocks the caller's thread. `bindings/uniffi/tests/api_surface.rs` MUST coerce every exported function and method to a function pointer of its exact type, as spec 027-core-api R16 does for `core`.
- R3 Every `[u8; N]` of the core boundary (`channel_id`, `server_id`, `ClientRef`, `PeerId`, the QR and fingerprint bytes) MUST cross as `Vec<u8>` in both directions. An incoming vector of the wrong length MUST return `FfiError::BadLength` before any host call. `u64` and `u32` MUST cross as uniffi's unsigned types (Kotlin `ULong` and `UInt`, Swift `UInt64` and `UInt32`), `&str` and `String` as `String`, `&[u8]` and `Vec<u8>` as `Vec<u8>` (Kotlin `ByteArray`, Swift `Data`), and `Option<T>` as an optional. Each conversion MUST be written once, as a `From` or `TryFrom` impl in `bindings/uniffi/src/convert.rs`, with an exhaustive `match`. The crate MUST deny `clippy::wildcard_enum_match_arm` and `clippy::match_wildcard_for_single_variants`, so that no `_` arm can hide a variant added to the core or the host, which then fails to compile here.
- R4 `FfiError` MUST have the variants of `core::Error` (spec 027-core-api R18) in the same order, `Store(StoreError)` becoming `Store { reason: FfiStoreError }` with the six variants of `StoreError` (spec 020-store-files R26), followed by one variant of its own, `Locked` (the host's `HostError::Locked`: no device is open). Its `Display`, which uniffi requires, MUST write the variant name and nothing else. The messages that the generated Kotlin and Swift code builds come from the fields, and none carries data. Every exported function and method, and `FfiHost`'s `Drop`, MUST run its body through one helper of `lib.rs` that catches a panic (`catch_unwind`, and for an async body `futures_util::FutureExt::catch_unwind` around the future) and returns `FfiError::Internal` (or, in `Drop`, nothing), so that no panic message crosses the boundary. The same helper MUST install, through a `std::sync::Once`, a panic hook that writes nothing, before its first body runs. The clients map errors by variant and never show the message.

**The handle**

- R5 `FfiHost::new(sink)` MUST build one `tokio` multi-thread runtime of 2 worker threads with time and I/O enabled, owned by the `FfiHost`, and a `privatechat_host::Host` over its handle, an adapter of the `FfiSink` as its `Sink`, and `SystemClock`. `FfiHost::with_fixed_clock(sink, now_ms)` MUST do the same with `FixedClock(now_ms)`; it exists for the vector tests of R13, and R10 keeps the apps from reaching it. Every async method MUST spawn its work on that runtime and await the join handle, so that a caller that stops awaiting (a cancelled coroutine or task) never cancels the host's work, only its own wait. `FfiHost`'s `Drop` MUST call `Host::drop_now` and then shut the runtime down in the background (`Runtime::shutdown_background`). The methods are:
  - `open(data_dir, storage_key)`, which returns `BadLength` for a `storage_key` that is not 32 bytes long, and otherwise copies the key into a `[u8; 32]`, builds it with `StorageKey::from_bytes` (which zeroes that array) and calls `Host::open`, mapping every error by R4 (`Store { reason: Locked }` when another holder has the `LOCK` file). `open` MUST zero the incoming `storage_key` vector on every path;
  - `lock()`, which calls `Host::lock`; after it every method other than `open` and `lock` returns `Locked`, and `open` opens again;
  - `network_changed()`, which calls `Host::network_changed` and returns at once;
  - `send`, `regenerate_identity`, `leave`, `set_socks5_proxy` and `probe_server`, which call the host's methods of the same name;
  - one method for each other method of `Device` in spec 027-core-api's Interface that spec 042-connection-host leaves to its callers, with the same name, the arguments of R3 and no `now`, through `Host::call`.
  The adapter hands every `FfiSink` call off at once: it calls the foreign method on a thread of the runtime and returns, and the platform implementation MUST NOT block or call `FfiHost` from inside it (spec 042-connection-host R5).
- R6 The adapter MUST pass every `HostEvent` to `FfiSink::core_event` as an `FfiHostEvent`, every state change to `FfiSink::connection_state` with the channel ids as byte vectors, and `locked` and `before_connect` as they are; `before_connect` of the adapter returns `true` without a foreign call, since no phone gates its connects.
- R7 `import_file` MUST hold its `password` vector, and `import_qr` its `text` vector (the invitation text holds `K_ch`, spec 011-config-format), in a `Zeroizing` buffer from entry, moved into the closure it gives to `Host::call`, so that it is zeroed on every path, a `Locked` that drops the closure unrun included. `export_file` MUST return an `FfiExportedFile { file, password }` whose password is bytes, and `export_qr` returns its text as bytes. No exported function MUST take or return a key, a seed, a password or an invitation text as `String` (spec 027-core-api R19).
- R8 `generate_storage_key()` MUST return 32 bytes drawn through the core. This spec amends spec 027-core-api by adding `pub fn generate_storage_key(out: &mut [u8; 32]) -> Result<(), Error>`, which fills the caller's array with libsodium's `randombytes_buf`. With it, all three platforms draw `K_db` from the one randomness source of AGENTS 2, and the desktop bridge (spec 041-desktop-bridge) has a source it may use. Outside `core::crypto`, a key exists as a plain `[u8; 32]` only in an array that its caller owns and zeroes: the one given to `generate_storage_key` and the one given to `StorageKey::from_bytes`, in this crate, in spec 041-desktop-bridge and in spec 020-store-files.

**The platform layer**

- R9 `bindings/uniffi/kotlin/` MUST hold a Gradle library whose package `org.privatechat.core` provides `class Core` and `interface CoreListener`, and `bindings/uniffi/swift/` a Swift package `PrivatechatCore`, for iOS 17 and macOS 14 or later, that provides `public final class Core` and `public protocol CoreListener`, isolated to a `@globalActor actor CoreActor`. `CoreListener` has the three methods of `FfiSink` with the generated records as arguments; `Core` implements `FfiSink` over it. The app builds one `Core` per process, with `Core.create(listener)`, which calls `core_init` once and `FfiHost::new`. `Core` has one `suspend` (Kotlin) or `async throws` (Swift) method per async method of `FfiHost` and per free function other than `core_init`, and `networkChanged()`, which does not suspend. Every Kotlin call runs in `withContext(NonCancellable)`, so that a caller cancelled during the call still receives its result. `Core` adds no executor and no ordering of its own: the host keeps the lifecycle in arrival order (spec 042-connection-host R4), and spec 053-device-security serialises the app's lock and unlock, each `open` awaiting the last `lock`. `Core.open(dataDir, storageKey)`, `importFile(bytes, password, …)` and `importQr(text, …)` MUST overwrite the key, password or text they were given with zeros after the call, on every path: Kotlin with `fill(0)` on the `ByteArray` in a `finally`, Swift with `resetBytes` on the `inout Data` in a `defer`. `generateStorageKey()` returns the new key, which the caller hands to spec 053-device-security and zeroes. `CoreListener`'s methods are called on a thread of the host's runtime, never the main thread; the app hands each call to its own main-thread state and returns (a `Channel` with `trySend`, a `Task { @MainActor in … }`). A `Core` built with a fixed clock, for R13, is `internal` to the library and its tests.

```rust
#[uniffi::export(with_foreign)]
pub trait FfiSink: Send + Sync {
    fn core_event(&self, event: FfiHostEvent);
    fn connection_state(&self, channels: Vec<Vec<u8>>, state: FfiConnectionState);
    fn locked(&self);
}   // before_connect is answered by the adapter (R6)

#[derive(uniffi::Object)]
pub struct FfiHost { /* the tokio Runtime, the privatechat_host::Host */ }

#[uniffi::export(async_runtime = "tokio")]
impl FfiHost {
    #[uniffi::constructor]
    pub fn new(sink: Arc<dyn FfiSink>) -> Arc<FfiHost>;
    #[uniffi::constructor]
    pub fn with_fixed_clock(sink: Arc<dyn FfiSink>, now_ms: u64) -> Arc<FfiHost>;   // R13 only
    pub async fn open(&self, data_dir: String, storage_key: Vec<u8>) -> Result<(), FfiError>;
    pub async fn lock(&self) -> Result<(), FfiError>;
    pub fn network_changed(&self);
    pub async fn send(&self, channel: Vec<u8>, body: String, display_name: Option<String>) -> Result<FfiSentView, FfiError>;
    pub async fn probe_server(&self, url: String) -> Result<FfiProbeResult, FfiError>;
    pub async fn import_file(&self, bytes: Vec<u8>, password: Vec<u8>, replace_broken: bool) -> Result<FfiImported, FfiError>;
    // one async method per Device method that spec 042-connection-host leaves to its callers, types by R3, no `now`
}

#[uniffi::export] pub fn core_init() -> Result<(), FfiError>;
#[uniffi::export] pub fn probe_hello(frame: Vec<u8>) -> Result<bool, FfiError>;
#[uniffi::export] pub fn default_server_url() -> String;
#[uniffi::export] pub fn generate_storage_key() -> Result<Vec<u8>, FfiError>;

#[derive(uniffi::Error)]
pub enum FfiError { BadLength, UnsupportedVersion, /* … the variants of core::Error in order … */ Internal,
                    Store { reason: FfiStoreError }, Locked }
#[derive(uniffi::Enum)]
pub enum FfiStoreError { Io, Locked, Corrupt, UnsupportedVersion, LogFull, OutboxFull }

// Records: FfiDeviceStatus, FfiBrokenChannel, FfiChannelInfo, FfiImported, FfiExportedFile, FfiSentView, FfiSettingsView,
// FfiReceived, FfiGap, FfiChannelStatus, FfiPeer, FfiMessage, FfiStranger, FfiOldKey, FfiFingerprint.
```

A `Device` method that returns no `Result` in spec 027-core-api (`channels`, `status`, …) returns `Result<_, FfiError>` here, whose only errors are `Locked` and `Internal`. `Frame`, `Store`, `Vault`, `StorageKey`, `DataDir`, `Device`, `ConnectionPlan`, `Route` and `Event` do not cross.

## Security

- Secrets cross by value in six places: the storage key out of `generate_storage_key` and into `open`, the `.chatcfg` password into `import_file`, the seven-word password out of `export_file` (ADR 0028), and the invitation text, which holds `K_ch`, into `import_qr` and out of `export_qr`. Rust zeroes what it receives (R5, R7), and `Core` zeroes the array the app gave it (R9). These copies are not zeroed: the buffers that uniffi's generated code allocates between the platform array and the Rust vector; the vectors that `generate_storage_key`, `export_file` and `export_qr` return, freed until the allocator reuses them; and the copies Swift makes of a `Data` it passes on (zeroing a shared buffer copies it first). The QR that spec 054-qr-invite draws from the exported text is the app's. This matches `docs/spec.md` §8 "FFI boundary": outside the core, non-retention is promised, not erasure. These are documented residuals.
- `Device`, `Config`, `Channel`, `Session` and the stores never cross. The handle is opaque (ADR 0037), and the records that come out carry no key, except the password, which crosses as the byte field `password` of `FfiExportedFile`, and the invitation text, which crosses as a bare byte vector. What `CoreListener` receives is what the user reads: message text, names and ids.
- `FfiError` carries no data, no panic message crosses, the panic hook writes nothing from the first call on (R4), and neither the crate nor the host installs a logger (spec 042-connection-host R2), so nothing of a message, a key or a path reaches `logcat`, the unified log or a crash report through the bindings.
- A wrong-length id returns an error before the host is called (R3). An id of the right length that names no open channel is the core's `UnknownChannel`.
- The host serialises every `Device` call behind its own lock and runs none on the caller's thread (spec 042-connection-host R4), so the one-writer rule of spec 027-core-api holds without the app knowing it. A one-second `import_file` delays frame processing by that second, well inside the 5 000 ms gap of spec 028-session-sans-io R9.
- The phones open no server connection of their own (R10), so they send the handshake, the headers and the proxy requests of spec 042-connection-host, and trust Mozilla's roots only (ADR 0041).
- Every platform builds libsodium from the pinned, signature-checked archive (R11), so the phones run the same library that the Rust vectors of spec 010-primitives-wrapper checked.

## Public API changes

One function is added to the core: `generate_storage_key(out: &mut [u8; 32]) -> Result<(), Error>` (R8), listed in spec 027-core-api's Interface and its `api_surface.rs`. Nothing else changes in the core. The bindings wrap the host of spec 042-connection-host, which wraps spec 027-core-api as it stands.

## Out of scope

- Where the storage key comes from and how it is wrapped: Keystore, Secure Enclave and the lock timeout (spec 053-device-security).

- Publishing the AAR or the Swift package anywhere; the apps build them from the repository.
- The desktop client, which links the host as a Rust crate (spec 041-desktop-bridge).
