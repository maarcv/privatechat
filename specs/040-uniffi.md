## Context

The Android and iOS clients reach the core through uniffi (`docs/spec.md` §9, ADR 0012). Spec 027-core-api fixed the boundary as one opaque handle, `Device` (ADR 0037), whose calls name channels and connections by id. This spec wraps that handle for Kotlin and Swift and nothing else. It covers the Rust crate that exports it, how each Rust type crosses the boundary, how secrets cross, the thread every call runs on, how the platform libraries are built, and the test that closes phase 4 on the mobile side (`docs/spec.md` §10).

The cryptography exists once, in Rust. What can still differ on a phone is the boundary: bytes, 64-bit numbers, optional fields and error variants must reach Kotlin and Swift unchanged. The vector test of this spec therefore drives the real `Device` from Kotlin and Swift with every vector that can reach it, decided with the human reviewer on 2026-09-26 (`docs/audit-log.md`, "Phase 4 drafts", Q1). The vectors of crate-internal functions stay with `cargo test`, which runs the same code.

**In plain words.** A small Rust crate turns `Device` into a Kotlin class and a Swift class, generated by uniffi. A thin hand-written layer on top runs every call on one background thread, in order, so a slow call (opening an invitation file costs about a second) never freezes the screen. That layer also wipes the password and the storage key from the app's memory right after handing them over. The apps use only that layer. Tests in Kotlin and Swift load the same vector files as Rust and check that importing invitations, reading fingerprints and recognising a server's greeting give exactly the same results on each platform.

## Requirements

**The crate**

- R1 The crate `privatechat-ffi` MUST live in `bindings/uniffi/`, be a member of the root workspace with `[lints] workspace = true` and `crate-type = ["cdylib", "staticlib", "lib"]`, and depend on exactly `privatechat-core`, `privatechat-store`, `uniffi` `=0.32.2` with `default-features = false`, and `zeroize`. It MUST contain no `unsafe` block of its own: the scaffolding that uniffi's macros generate is the only unsafe code in it. The code generator MUST be a separate crate, `privatechat-uniffi-bindgen` in `bindings/uniffi/bindgen/` (`publish = false`), the only crate that enables uniffi's `cli` feature, so that no `log` and no generator code is linked into the library the apps ship (measured on 2026-09-26: `cli` brings in `log`, and the runtime alone does not). `cargo deny --all-features check` MUST stay green with no new exception (measured: the runtime reaches `getrandom` and `fastrand` only through `tempfile`, which `deny.toml` already allows).
- R2 The crate MUST export with proc macros only (no UDL, `docs/spec.md` §9). It MUST export exactly the object `FfiDevice`; the free functions `init`, `probe_hello`, `default_server_url` and `generate_storage_key`; one uniffi `Record` for each struct and one uniffi `Enum` for each enum that spec 027-core-api's Interface lists as `pub` for the bindings, with the same name prefixed `Ffi`, the same fields and variants in the same order, types translated by R3; and `FfiError` and `FfiStoreError` (R4). `bindings/uniffi/tests/api_surface.rs` MUST coerce every exported function and method to a function pointer of its exact type, as spec 027-core-api R16 does for `core`.
- R3 Every `[u8; N]` of the core boundary (`channel_id`, `server_id`, `ClientRef`, `PeerId`, the QR and fingerprint bytes) MUST cross as `Vec<u8>` in both directions. An incoming vector of the wrong length MUST return `FfiError::BadLength` before any `Device` call. `u64` and `u32` MUST cross as uniffi's unsigned types (Kotlin `ULong` and `UInt`, Swift `UInt64` and `UInt32`), `&str` and `String` as `String`, `&[u8]` and `Vec<u8>` as `Vec<u8>`, and `Option<T>` as an optional. Each conversion MUST be written once, as a `From` or `TryFrom` impl in `bindings/uniffi/src/convert.rs`. The crate MUST deny `clippy::wildcard_enum_match_arm`, so that a variant added to the core fails to compile here instead of being mapped to a catch-all.
- R4 `FfiError` MUST have the variants of `core::Error` (spec 027-core-api R18) in the same order, `Store(StoreError)` becoming `Store { reason: FfiStoreError }` with the six variants of `StoreError` (spec 020-store-files), followed by one variant of its own, `Closed` (R6). Its `Display` MUST write the variant name and nothing else: uniffi needs a message, and it carries no data, so no content, key or path can reach a platform log through it. The clients map errors by variant and never show the message.

**The handle**

- R5 `FfiDevice` MUST hold a `Mutex<Option<Device>>`. Its constructor `open(data_dir, storage_key, now)` MUST return `FfiError::BadLength` for a `storage_key` that is not 32 bytes long. Otherwise it MUST copy the key into a `[u8; 32]`, build the key with `StorageKey::from_bytes` (which zeroes that array), and call `DataDir::open` on the path and then `Device::open` with that directory as its vault, mapping every error by R4 (`Store { reason: Locked }` when another process holds the `LOCK` file). Each method of `Device` in spec 027-core-api's Interface MUST be a method of `FfiDevice` with the same name and the arguments of R3. Each method takes `&self` and holds the lock for the whole call. `open` MUST zero the incoming `storage_key` vector on every path.
- R6 `close(now)` MUST call `Device::flush(now)`, drop the `Device` whatever `flush` returned, and return `flush`'s result. Dropping the `Device` closes its files and zeroes `K_db` (spec 027-core-api R24). After `close`, every method MUST return `FfiError::Closed` and `close` again MUST return `Ok`. A lock poisoned by an earlier panic MUST make every later call return `FfiError::Internal`.
- R7 `import_file` MUST zero its `password` vector before returning, on every path. `export_file` MUST return an `FfiExportedFile { file, password }` whose password is bytes. No exported function MUST take or return a key, a seed or a password as `String` (spec 027-core-api R19).
- R8 `generate_storage_key()` MUST return 32 bytes drawn through the core. This spec amends spec 027-core-api by adding `pub fn generate_storage_key(out: &mut [u8; 32]) -> Result<(), Error>`, which fills the caller's array with libsodium's `randombytes_buf`. With it, all three platforms draw `K_db` from the one randomness source of AGENTS 2, and the desktop bridge (spec 041-desktop-bridge) has a source it may use. The new key and `StorageKey::from_bytes` are the only two places where a key exists as a plain array, and in both the array belongs to the caller, who zeroes it.

**The platform layer**

- R9 `bindings/uniffi/kotlin/` MUST hold a Gradle library whose package `org.privatechat.core` provides `class Core`. `Core` owns one single-thread dispatcher and has one `suspend` method per method of `FfiDevice`, which runs the call on that thread in the order the methods were called. `Core.open(dataDir, storageKey: ByteArray, now)`, `importFile(bytes, password: ByteArray, …)` and `generateStorageKey(): ByteArray` MUST fill every `ByteArray` they were given with zeros in a `finally` after the call. `bindings/uniffi/swift/` MUST hold a Swift package `PrivatechatCore` with `final class Core: Sendable`, which does the same with one serial `DispatchQueue`, `async throws` methods through `withCheckedThrowingContinuation`, and `[UInt8]` arguments overwritten with zeros in a `defer`. Both MUST re-export the generated records, enums and errors under their own names, by `typealias`.
- R10 No source file under `clients/android/` or `clients/ios/` MUST import the generated module (`uniffi.privatechat_ffi` in Kotlin, `privatechat_ffi` in Swift): the apps reach the core through `Core` alone. `scripts/check_bindings_use.sh` MUST enforce this in CI. Every `Device` call therefore runs off the UI thread (ADR 0037), and calls to one device never interleave.
- R11 `scripts/build_bindings.sh` MUST take one argument, `host`, `android` or `ios`, and build the library, then generate the Kotlin or Swift sources with `privatechat-uniffi-bindgen generate --library` into `target/uniffi/`. The generated sources MUST NOT be committed. `android` MUST build the `.so` for `arm64-v8a`, `armeabi-v7a` and `x86_64` at API level 26 with `cargo ndk` and the NDK version pinned in the script. `ios` MUST build an XCFramework from `aarch64-apple-ios` and `aarch64-apple-ios-sim`. `host` MUST build the library that the Kotlin tests load on the JVM and the Swift tests link on macOS. libsodium MUST be built from the archive that `libsodium-sys-stable` pins, for every target: `SODIUM_LIB_DIR` MUST NOT be set, so no platform links a libsodium other than the one that was audited (spec 010-primitives-wrapper, "Bumping libsodium").
- R12 A CI job `bindings` MUST run on a macOS runner. It MUST run `scripts/build_bindings.sh` for all three arguments, `./gradlew test ktlintCheck detekt` in `bindings/uniffi/kotlin/` with the JDK and Gradle wrapper pinned there, `swift test` and `swift format lint --strict` in `bindings/uniffi/swift/`, and `scripts/check_bindings_use.sh`. `.github/CONTRIBUTING.md` MUST list the same commands (AGENTS 17).

**Vectors**

- R13 Kotlin and Swift MUST each check the vector files `specs/vectors/011.json`, `014.json` and `028.json` through `Core`, read in place from the repository with the platform's JSON parser (`kotlinx-serialization-json` as a test dependency, Foundation's `JSONSerialization`). Each check uses a fresh data directory in a temporary folder and a key from `generateStorageKey`:
  - 011: each positive vector through `importQr` with the vector's `now`, its QR text or else the record encoded as base64url with no padding by the platform codec, gives an `FfiImported` whose `id`, `serverUrl`, `suggestedName` and `ttlSeconds` equal the expected values. `chatcfg_reference` through `importFile` with its password gives the same `id`. Each negative vector gives the `FfiError` variant its `error` names.
  - 014: after importing the QR of 011 `config_reference`, `verifyScanned` with the QR of `qr_reference` gives its `pk_u`, and `fingerprint` of that peer gives the `words`, `short` and `qr` that the vectors expect. `qr_wrong_prefix`, `qr_wrong_length`, `qr_standard_base64` and `qr_padding` give `BadPayload`, and `qr_other_channel` gives `WrongChannel`.
  - 028: each vector's frame through `probeHello` gives `true` for a `hello` whose `event` is `accepted`, `false` for one whose `event` is `unsupported_server`, and `BadPayload` for every other frame.
  Each test MUST fail on a vector of those files that it neither checks nor lists in its exclusion list with a reason, as `check_all` does (spec 015-test-vectors R3). The only allowed exclusions are the 014 vectors that start from a bare `fp` or another channel's fingerprint (`words_zero`, `words_ones`, `words_bit_131`, `fingerprint_other_channel`), which no `Device` call reaches.
- R14 This spec amends spec 014-fingerprint, in its Vectors section, so that every vector carrying a `channel_id`, except `fingerprint_other_channel` and `qr_other_channel`, uses the `channel_id` of 011 `config_reference`; so that `qr_reference` carries the `pk_u` of `fingerprint_reference`; and so that `words_reference` holds the words of that fingerprint. It amends spec 028-session-sans-io so that every vector of `028.json` carries the input `frame_type`, the number at key 0 of its frame. Both amendments were written into those specs on 2026-09-26. In the pull request that marks this spec `accepted`, the phase 4 exit criterion of `docs/spec.md` §10 MUST be reworded to: "Kotlin and Swift reproduce, through the bindings, every vector of spec 040-uniffi's list; the empty Tauri app opens a channel against the server of spec 034-docker".

## Limits

| Input | Range | Out of range |
| --- | --- | --- |
| `storage_key` | exactly 32 bytes | `BadLength`, nothing opened |
| `channel`, `server_id`, `client_ref` | exactly 16 bytes | `BadLength`, no `Device` call |
| `peer`, `pk` | exactly 32 bytes | `BadLength`, no `Device` call |
| Calls in flight per `Core` | one; the others wait in call order | — |
| Any other argument | the range of the spec that defines the call | that spec's error |

A `Device` method that returns no `Result` in spec 027-core-api (`channels`, `connections`, `on_frame`, `on_tick`, …) returns `Result<_, FfiError>` here, and the only error is `Closed` (or `Internal` for a poisoned lock). `Frame`, `Store`, `Vault`, `StorageKey` and `DataDir` do not cross. `AckOutcome` stays inside the core.

## Security

- Secrets cross by value only in three places: the storage key into `open`, the `.chatcfg` password into `import_file`, and the seven-word password out of `export_file` (ADR 0028). Rust zeroes what it receives (R5, R7), and `Core` zeroes what the app gave it (R9). The copies that uniffi's generated code makes between the platform array and the Rust vector (a buffer that Rust allocates and frees, and the platform's own array copies) are not zeroed. This matches `docs/spec.md` §8 "FFI boundary": outside the core, non-retention is promised, not erasure. The seven-word password that `export_file` returns sits in a buffer that is freed without being zeroed, until the allocator reuses it. This is a documented residual.
- `Config`, `Channel`, `Session` and the stores never cross. The handle is opaque, and only records without secrets come out (ADR 0037).
- `FfiError` carries no data (R4), and the crate emits no log and links no logging crate (R1), so nothing of a message, a key or a path reaches `logcat` or the unified log through the bindings.
- A wrong-length id returns an error before the core is called (R3). An id of the right length that names no open channel is the core's `UnknownChannel`.
- `Core` serialises every call on one thread (R9, R10). The socket loop of each app therefore cannot interleave an `on_frame` with a `send` of the same device, and the one-writer rule of spec 027-core-api holds without the app knowing it.
- Every platform builds libsodium from the pinned, signature-checked archive (R11), so the phones run the same library that the Rust vectors of spec 010-primitives-wrapper checked.

## Public API changes

One function is added to the core: `generate_storage_key(out: &mut [u8; 32]) -> Result<(), Error>` (R8), listed in spec 027-core-api's Interface and its `api_surface.rs`. Nothing else changes. The bindings wrap spec 027-core-api as it stands.

## Test cases

- T01 (covers R1): CI step `s040_t01_r01_crate_deps`: `cargo tree -p privatechat-ffi -e normal` names only the dependencies of R1 and theirs, with no `log` among them; `cargo deny --all-features check` green; `grep -rn 'unsafe' bindings/uniffi/src` finds nothing.
- T02 (covers R2): `s040_t02_r02_api_surface`: `tests/api_surface.rs` compiles.
- T03 (covers R3): `s040_t03_r03_lengths`: `send` with a 15-byte and a 17-byte channel, `label` with a 31-byte peer and `fingerprint` with a 33-byte `pk` each return `BadLength`, with nothing committed; a 16-byte unknown channel returns `UnknownChannel`; a `u64` of 2^63 + 5 given as `now` to `import_qr` of 011 `config_no_invite` imports the channel (no sign is lost).
- T04 (covers R4): `s040_t04_r04_error_mapping`: every `core::Error` and `StoreError` variant converts to the `FfiError` variant of the same name, in order, and `Display` of each is exactly its name.
- T05 (covers R5): `s040_t05_r05_open`: a 31-byte key → `BadLength`; a second `open` of the same directory → `Store { reason: Locked }`; the private function behind `open`, which takes the key vector by `&mut`, leaves it all zeros after a success and after each failure.
- T06 (covers R6): `s040_t06_r06_close`: after `close`, `channels` and `send` → `Closed`; a second `close` → `Ok`; a `flush` failure (a `FailingVault`) is returned and the `Device` is dropped all the same.
- T07 (covers R7): `s040_t07_r07_password_bytes`: the password vector is zeros after an `import_file` that succeeds and after one with `BadPassword`; `export_file` returns a 7-word password as bytes.
- T08 (covers R8): `s027_t25_r08_generate_storage_key` in `crates/core` (as part of the amendment of 027): two calls give different arrays of 32 bytes; `s040_t08_r08_generate`: the exported function returns 32 bytes.
- T09 (covers R9): Kotlin `s040_t09_r09_core_thread` and Swift `s040_t09_r09CoreQueue`: 100 concurrent calls from 8 coroutines or tasks run one at a time, in submission order per caller, on a thread that is not the caller's; the key and password arrays passed to `open` and `importFile` are all zeros afterwards, after a success and after a failure.
- T10 (covers R10): `scripts/check_bindings_use.sh` fails on a fixture file under a temporary `clients/android/` tree that imports `uniffi.privatechat_ffi`, and passes on the real tree.
- T11 (covers R11): CI step `s040_t11_r11_builds`: the three builds finish; the Android and iOS artefacts exist for each named target; `git status --porcelain` shows no generated source.
- T12 (covers R12): CI job `bindings`, and the same commands in `.github/CONTRIBUTING.md`.
- T13 (covers R13): Kotlin `s040_t13_r13_vectors_011`, `…_014`, `…_028` and the Swift tests of the same names: every vector of the three files is checked or excluded with its reason; a vector name added to a file and not handled fails the test.
- T14 (covers R14): `check_s040_t14_r14_amendments` in `scripts/doc_lint.py`, once this spec is `accepted`: §10 carries the new exit criterion, and specs 014 and 028 carry the amended vector inputs.

## Vectors

None of its own. It checks through the bindings the vectors of specs 011-config-format, 014-fingerprint and 028-session-sans-io that reach `Device` (R13), after the amendments of R14. The vectors of specs 010, 012, 013, 017 and 031 test crate-internal functions: `cargo test` checks them on the same code, and no platform call reaches them on its own.

## Acceptance criterion

`cargo test -p privatechat-ffi s040_`, `./gradlew test` in `bindings/uniffi/kotlin/` and `swift test` in `bindings/uniffi/swift/` green; the CI job `bindings` green, with the Android and iOS builds. With spec 041-desktop-bridge accepted and green as well, phase 4 closes. Non-automatable: a second person reads `Core` in both languages next to spec 027-core-api's Interface and confirms that every method is there, that none is called from the caller's thread, and that every byte array holding a secret is zeroed.

## Out of scope

- Where the storage key comes from and how it is wrapped: Keystore, Secure Enclave and the lock timeout (spec 053-device-security).
- The sockets, TLS, SOCKS5, backoff and the one-second tick on Android and iOS (specs 051-android-mvp, 052-ios-mvp).
- Running the libraries on a device or an emulator; the first on-device run is in phase 5.
- Publishing the AAR or the Swift package anywhere; the apps build them from the repository.
- The desktop client, which links the core as a Rust crate (spec 041-desktop-bridge).

None. Decided with the human reviewer on 2026-09-26 (`docs/audit-log.md`, "Phase 4 drafts", Q1): the Kotlin and Swift vector test drives `Device` with the vectors that reach it, not a second test-only library that re-exports internal functions.
