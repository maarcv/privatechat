## Context

Phase 1 made sealing and opening a message a pure function (spec 013-wire-message). `Channel` is where that function meets the state: the user's own key, the send counter, the `outbox`, the cursor, the peers and the kept signatures, all loaded from one `Store` and changed by one commit per operation (ADR 0020, AGENTS 23). It implements `docs/spec.md` §4 "Send counter", steps 5, 6 and 8 of "Verification on receive" around 013's `verify` and `open`, "Messages from one's own key" (ADR 0029), and the `outbox` rules of ADR 0034 for ordinary messages.

The peers are spec 022-peers-tofu's, the message list 023-ttl-purge's, a received retirement and `read_only` 024-key-retired's, regeneration and the pending `key_retired` 025-identity-regen's, the room check and eviction 026-peer-limits'. This spec gives them the one place they plug into: the receive pipeline of R9 and the commit of R2. Until those specs are implemented, their checks are hooks that change nothing: no peer is retired and every unknown finds room. `Channel` is crate-internal: the clients reach it only through the `Device` of spec 027-core-api.

**In plain words.** A `Channel` is one channel on this device. When you send, it takes the next number, seals the message, puts the sealed copy in the waiting list and writes all of that to disk before anything can leave; if the write fails, nothing leaves. When a message arrives, it first checks there is room on disk; then it lets spec 013 check everything that needs no memory; then it asks the questions that need memory — is this key retired, is there room for a stranger, has this number been seen — and only then opens the text. Whatever happened, the channel writes at most one thing to disk. A message that claims to come from your own key is your echo only if your device kept its exact signature; otherwise someone else holds your key, and the channel raises the alarm, even when the disk is full.

## Requirements

**State and commit**

- R1 `Channel` MUST hold in memory the `ChannelState` and the log records of the last successful commit, plus these in-session values: the cursor, `synced_at` and `truncated_at` not yet committed (R20, R24), the gaps of R24, the ignored-keys set of spec 026-peer-limits, an index of `(purge_at, entry length)` of its records ordered by `purge_at` (built at load, extended at each commit, rebuilt after a compaction), from which it knows the bytes expired at any `now` and the oldest expiry, the time of its last compaction, `clock_off` (R25, false when the `Channel` is created or loaded), the `now` of the latest call that took one, and the values `carry_session` copies (the gaps of R24, the ignored-keys set of spec 026-peer-limits R6 and `clock_off`, committing nothing, overriding the reset at load), whether the peers or the gaps changed since `take_peers_changed()` was last called — a peer record created or removed, or its `label`, `verified`, `muted`, `retired_at` or `last_display_name` changed, or `own_display_name` changed (spec 022-peers-tofu R13 reads it), or the gaps of R24 changed, but not `last_seen` or `max_counter` alone, so that an ordinary message does not make the client re-read every list; set when the `Channel` is created or loaded — and the outcomes queued for `take_outcomes()`.
- R2 Every method that changes state MUST build one `WriteBatch` from `ChannelState::duplicate` (spec 020-store-files) of the current state, call `Store::commit(&batch)` once, and move the batch's state and records into memory only after `Ok`; on `Err` it MUST return `Error::Store(e)` and keep the previous copy.
- R3 A `decrypt` that returns an error of R9 MUST commit nothing but the cursor of R20, and only when that cursor-only commit is due, with five exceptions: the echo acknowledgement of R13, the own-key values and held removal of R19, which any successful commit persists and performs, the own-key event of R14, the commit of R19, and the removal of overtaken old-key entries at step 5 (R9). A `decrypt` that fails with `Error::Store` MUST leave the cursor unchanged and commit nothing but the commit of R19.

**Create and open**

- R4 `Channel::create(config, store)` MUST call `load`; on `None` it MUST draw a 32-byte identity seed with `Secret::random` and commit a first state with that seed, `identity_epoch = 0`, `send_counter = 0`, no cursor, no peers, an empty `outbox` and a copy of the config without `invite_expires_at`, and return the channel and `true`.
- R5 On a loaded state, `create` MUST return `Error::ConfigMismatch` when the stored config has another `channel_id` or another `server_url`, and otherwise the stored channel unchanged and `false`, with no commit (`docs/spec.md` §5).
- R6 `Channel::open_stored(store)` MUST call `load`, return `Error::Store(StoreError::Corrupt)` on `None`, return any load error, and a stored config that fails to decode, as `Error::Store` (`UnsupportedVersion` when the config's decode returns it, so that a newer app's data is not reported as corrupt and is offered for removal only behind the confirmation of spec 027-core-api R3, and `Corrupt` otherwise), and otherwise the stored channel, with no commit; `config()` MUST return the stored `Config` and `dir_name()` the store's `name()`.

**Sending**

- R7 `encrypt(body, display_name, now)` MUST, in this order: return `Error::RetiredKey` when `read_only` is set (spec 024-key-retired); return `Error::CounterExhausted` when `send_counter` is `2^64 − 1`; return `Error::Store(StoreError::OutboxFull)` when the `outbox` holds 31 ordinary entries; apply the headroom of R18; resolve the name (at most `MAX_NAME` of spec 020-store-files) (a non-empty `Some(name)` → that name, stored as `own_display_name`; `Some("")` → no name, and the stored one cleared; `None` → the stored one); build the `text` payload with `sent_at = now − now mod 60 000`; draw the nonce with `random_bytes`; `seal` with `counter = send_counter`; and commit `send_counter + 1`, the `outbox` entry and the own log record in one commit before returning the `ClientRef`. The blob MUST leave the core only through `outbox()` (R22). Every refusal of this requirement, and a failure of `validate` (`Error::BadPayload`), MUST commit nothing.
- R8 The `outbox` entry MUST carry a fresh 16-byte `client_ref` from `random_bytes`, used for every publish of that entry, `kind` 0, the `sent_at`, the blob, the unmasked signature `seal` returned, `under_retired_key` false and the counter; the own log record MUST be a message record with `own` true, the same `client_ref`, `received_at = now`, no `server_id`, one's own `pk_u`, the counter, the `sent_at` of R7, the body, the name, and the `purge_at` of R26.

**Receiving**

- R9 `decrypt(blob, server_id, received_at, now)` MUST run, in this order, returning the first failure: the headroom of R18, whose failure returns the compaction's `Error::Store(e)` when R18's compaction failed, and otherwise runs the check of R19 and returns `Error::Store(StoreError::LogFull)`; `verify` of spec 013-wire-message (steps 1–4); step 5: a `sender_pk` that is a retired peer or one of `own_old_keys` → `Error::RetiredKey`, except that for the key being retired (`retiring_seed` present, spec 025-identity-regen) a blob whose signature is not that of one of its own `outbox` entries is first opened, and when it is within reach (R14) it removes, as by R22 with outcomes queued as `NotDelivered`, every ordinary entry `under_retired_key` whose counter is at or below the blob's, since receivers that took the thief's blob reject them — never the pending `key_retired`; then an unknown `pk` other than one's own `pk_u` (never a peer, `docs/spec.md` §4 step 5) for which spec 026-peer-limits finds no room → `Error::PeerLimit`; step 6: a `server_id` equal to that of a retained message or seen record → `Error::Replay`; for a peer, a (`sender_pk`, `counter`) pair equal to that of a retained seen record, or `counter ≤ max_counter` → `Error::Replay`, and for one's own `pk_u` the echo rule of R13 in place of `max_counter`, then, when it found no echo, a retained seen record from one's own `pk_u` with the same `counter` → `Error::Replay` (a republished foreign blob, whose alert is already set); then `Verified::open`, whose `BadSignature` is returned as is.
- R10 After `open`, `Content::Stale` of spec 013 MUST be returned as `Error::Expired`, with only the cursor of R20, except the own-key event of R14. For a message from a peer, with `r = max(received_at, sent_at − 360 000)` when `open` read a `sent_at` and `r = received_at` otherwise, `min(r, now) + ttl_ms < now` MUST also be returned as `Error::Expired` with only the cursor: a message that would expire before it is shown is not consumed, and a server cannot date a message earlier than its signer did by more than the margin. Messages from one's own key follow R13 and R14 instead.
- R11 A consumed message that is not stale, from a peer, MUST be committed in one commit as: the log record, whose `received_at` is `min(r, now)` with `r` of R10, the time it is shown at — never later than its arrival and never earlier than its signed `sent_at` minus the margin (`Content::Message` → a message record with its fields; `Content::Unreadable` → a message record with `content` 2, no body, and `sent_at` when `open` read one; none where spec 024-key-retired R2 says so), with each message record a seen record (spec 020-store-files: its `server_id`, `sender_pk` and `counter`), the peer as spec 022-peers-tofu updates or creates it with `max_counter = counter` and `last_seen = now`, what specs 024-key-retired and 026-peer-limits change in that commit, and the cursor. `decrypt` MUST return `Ok(Some(received))` when it appended a message record and `Ok(None)` when it appended none.
- R12 A `Received` MUST carry the `server_id`, the sender (`Sender::Peer { pk }`, or `Sender::OwnKeyElsewhere { pk }` for R14), the `received_at` of its record (R11), `sent_at` when read, `expires_at` (the record's `received_at + ttl_ms`, spec 023-ttl-purge R1), and the content, a `MessageContent`: `Text { body, display_name }`, `KeyRetired` or `Unreadable`.

**One's own key** (ADR 0029)

- R13 For a blob whose `sender_pk` is one's own `pk_u`, step 6 MUST be: if its unmasked signature (`Verified::signature`) equals under `ct_eq` the signature of a kept-signature record whose `epoch` is the current `identity_epoch`, return `Error::Replay`, and when `own_key_used_elsewhere` is not set, a not-delivered record names the `client_ref` that kept signature carries, no acked record names it, no acked record names an own message record from the current `pk_u` with a higher counter (an `ack` of a later entry, by R17, means receivers reject this one as `Replay`), and the push's `received_at` and the clamped time `t` meet R17's two conditions, first append an acked record for that `client_ref` with the push's `server_id` and `t`, and queue a `Delivered` outcome carrying both, since the echo proves the server stored it in time — once, so a repeated echo writes nothing; if it equals that of an ordinary `outbox` entry that is not `under_retired_key` and not covered by a held removal of R19 (such an entry counts as removed by R14: `Error::Replay`, no acknowledgement, and the commit of this `decrypt` performs the held removal), apply R17 to that entry with the push's `server_id` and `received_at` in the commit of this `decrypt`, queue its outcome for `take_outcomes()`, and return `Error::Replay`, so that an `ack` lost to a reconnect is not a lost message; otherwise, unless a retained seen record from one's own `pk_u` has the same `counter` (`Error::Replay`, R9), run `open` and apply R14.
- R14 After `open` for one's own key and not an echo: when `open` read a `sent_at` and `sent_at + 2·(ttl_ms + 360 000) < now`, the message MUST be discarded as `Error::Expired` with only the cursor and no event; otherwise `own_key_used_elsewhere` MUST be set in the commit of the outcome, stale or not, and in addition, only when the message is not stale, the log record of R11 with `own` false and, when `counter ≥ send_counter`, `send_counter = counter + 1`, or `2^64 − 1` when `counter` is `2^64 − 1`; and, whenever the message is within reach — `open` read no `sent_at`, or `sent_at + ttl_ms + 720 000 ≥ min(received_at, now)` and `sent_at ≤ min(received_at, now) + 2·(ttl_ms + 360 000)`, the widest dates at which a copy stored now could still be accepted by a member whose clock is up to the margin off — even if it is dated too far ahead, the removal, as by R22 (kept signature, not-delivered record, outcome queued as `NotDelivered`), of every ordinary `outbox` entry not `under_retired_key` whose counter is at or below the message's counter, or of every such entry when the message is a `key_retired`, since every receiver that accepted the foreign message rejects them. A message with no readable `sent_at` raises the event: this device never seals one, so it cannot be an old echo. `own_key_used_elsewhere` stays set until spec 025-identity-regen clears it.
- R15 Every kept signature MUST last until `sent_at + 3·(ttl_ms + 360 000)`: inside its `outbox` entry while the entry lives, and afterwards as a kept-signature record with the entry's `client_ref`, the current `identity_epoch` and that time as `purge_at`, appended in the commit that removes the entry (R17, R22, R31), unless the entry is `under_retired_key`.

**Acknowledgement, the log and the cursor**

- R16 `acked(client_ref, server_id, received_at, now)` MUST return an `Outcome` of `AckOutcome::Ignored`, with no commit, for a `client_ref` that names no current `outbox` entry. A `key_retired` entry is spec 025-identity-regen's.
- R17 For an ordinary entry, `acked` MUST, in one commit, remove the entry, remove as by R22 (outcomes queued as `NotDelivered`) every ordinary entry of the same key with a lower counter still in the `outbox` — the server stores one connection's publishes in order, so an entry it refused earlier and would store later reaches every receiver as `Replay` — append the kept signature of R15, and append an acked record (`server_id`, and `min(max(received_at, sent_at − 360 000), now)` as its `received_at`, so that a server can date the `ack` neither ahead of this device's clock nor earlier than the message was sealed) and return `Delivered` when the server's own `received_at` satisfies `|received_at − sent_at| ≤ ttl_ms + 360 000` (checked on both sides against the unclamped time, `docs/spec.md` §4 and ADR 0034, so that a sender clock off by more than the margin cannot hide a loss behind an `ack`) and the clamped time `t` satisfies `t + ttl_ms ≥ now`, so that a message it reports delivered is one receivers can still show, or a not-delivered record and `NotDelivered` otherwise; `acked` returns an `Outcome` carrying the outcome and `t`, from which spec 028-session-sans-io builds its event.
- R18 `encrypt` and `decrypt` MUST first check that `log_len() + 65 580 + 1 048 576 ≤ 67 108 864` (a maximal entry with its 4-byte length, and a reserve); when it fails, they MUST run `relieve_headroom(now)`: when the records whose `purge_at` is below `now` take at least `max(1 048 576, log_len() + 1 114 156 − 67 108 864)` bytes, so that the compaction restores the room, and the channel's last compaction is at least 600 000 ms old (no compaction yet since the channel was loaded counts as old enough, and a recorded time later than `now` is reset to `now`), call `Store::compact(state, now)`, drop those records from memory and record `now` as the last compaction, which every compaction attempt, `purge_expired` included, does whether it succeeds or fails; then they check again; a compaction that fails leaves memory as it was and makes them return its `Error::Store(e)`, so that spec 027-core-api R14 reopens the channel at once, its last attempt carried over, onto whichever log stands (spec 020-store-files R11); `last_compaction()` and `set_last_compaction(at)` read and set the time of the last attempt; `relieve_headroom` called alone returns `Ok(true)` when it compacted, `Ok(false)` when less than that threshold had expired or the ten-minute limit held it off, and the compaction's `Error::Store(e)` when it failed (a store it poisoned fails the next commit with `Io`, spec 020-store-files R11); otherwise they return `Error::Store(StoreError::LogFull)` with nothing committed. The check reads no byte of the blob, so it does not depend on the verdict; a compaction frees at least the reserve and runs at most once every ten minutes, so a flood can make the device rewrite at most one log every ten minutes, and between two compactions the channel stays full (spec 028-session-sans-io R10). The reserve is for the commits that add no message: acks, `outbox`, `abandon`, regeneration and the check of R19.
- R19 `check_own_key(blob, received_at, now)` MUST run `verify` and `Verified::open` of spec 013 with no state, and, for a blob from one's own `pk_u` whose signature matches neither a kept signature of the current epoch nor an `outbox` entry (R13), whose `sent_at` is unreadable or not older than `now − 2·(ttl_ms + 360 000)`, commit — no message record, no cursor — `own_key_used_elsewhere` and R14's changes: when the blob is not stale, the send counter bump and, for a `key_retired`, `read_only` (spec 024-key-retired R3), and when it is within reach (R14), the removal of the overtaken entries not `under_retired_key` with their kept-signature and not-delivered records (or all such entries for a `key_retired`), outcomes queued; when that commit fails with `LogFull`, it commits the flag, the counter and, for a `key_retired`, `read_only` alone, and holds the pending removal in memory as the held overtaken counter, with the guards stated below (a later commit that carries a held removal and fails with `LogFull` is retried once without it, the removal staying held); when that commit, or this fallback, fails with another store error, it holds in memory `own_key_used_elsewhere`, when the blob is not stale the send counter bump and, for a `key_retired`, `read_only`, and when it is within reach the counter through which ordinary current-key entries are overtaken (all of them for a `key_retired`) — `status()`, `encrypt` and `send_counter()` read these, `outbox` never hands out an entry the held removal covers, and the next successful commit persists them and performs the removal with its records and `NotDelivered` outcomes, queued for `take_outcomes()`; entries the held removal covers count as absent for R16 and R17, so an `ack` of one is `Ignored` — and returns `Ok(true)` without reporting the error (an exception to R1 and R2; R22's `store_error` is the other, to R2's return alone), so that a disk that cannot be written does not hide the alert; `held_own_key()` returns these held values, and `hold_own_key(held)` sets them in memory on another instance (the flag only when `held` has it, a send counter of at least the floor, the larger overtaken counter), commits nothing, and leaves the next successful commit to persist them. For a blob from the key being retired whose signature matches none of its `outbox` entries and that is within reach (R14), it applies instead the step-5 removal of R9, within the reserve; when that commit fails with a store error, it holds the counter in `old_key_overtaken_through`, which `outbox`, `acked` (the covered entries absent for R16 and R17) and the next successful commit treat as for the current key (`decrypt`'s own step-5 removal does the same when its commit fails). It commits whenever the state changes and returns `true` for any blob from one's own `pk_u` of this kind, whether or not the flag was already set. `decrypt` runs it when the headroom fails, and spec 028-session-sans-io runs it on every push of a channel stalled by a full log, so that a full log cannot hide the alert nor raise it for an old replay.
- R20 The cursor MUST become `max(cursor, min(received_at, now))` on every `decrypt` that does not fail with `Error::Store`, except a push with `received_at + ttl_ms < now`, which the server would not hold if the clocks agreed and which therefore leaves the cursor where a corrected clock can fetch it again; it stays in the server's time and no other call moves it. `synced(now)`, which spec 028-session-sans-io calls at `ok` and on every tick while the channel is subscribed and not stalled (except after a gap of more than 5 000 ms, spec 028-session-sans-io R9), MUST set `synced_at = now` (state key 17 of spec 020-store-files, local time, used only to judge truncation). Both are written with every commit; a commit whose only change is the cursor MUST be made only when its minute (`v − v mod 60 000`) differs from the committed one's, and a commit whose only change is `synced_at` only when the committed `synced_at` is absent, later than `now`, or older than `min(ttl_ms / 2, 3 600 000)`, the in-memory values waiting otherwise; `flush(now)` MUST commit every pending value — cursor, `synced_at`, `truncated_at`, and the own-key values held only in memory (R19) — at once, for the lock of spec 027-core-api; `probe(now)` MUST commit the in-memory state once, even with nothing pending, to test that the store can be written (spec 027-core-api R12); `synced`, `flush` and `probe` return `Error::Store` like any commit.
- R21 `ttl_ms`, `EXPIRY_MARGIN_MS` and `KEY_RETIRED_COUNTER` MUST be those of spec 013-wire-message, and every time computation of this spec MUST saturate.

**The `outbox`**

- R22 `outbox(now, in_flight, withhold_current)` MUST remove, in one commit, every ordinary entry whose `sent_at + ttl_ms + 360 000 < now` when it is not in `in_flight`, or `sent_at + ttl_ms + 420 000 < now` when it is (a minute of grace for its `ack`), appending its kept signature and a not-delivered record, and return an `OutboxStep` with, in `outbox` order, the (`ClientRef`, blob) of every remaining entry not in `in_flight` — only the pending `key_retired` and the entries `under_retired_key` when `withhold_current` is set (spec 028-session-sans-io R10) — and the (`ClientRef`, `sent_at`) of every entry it removed; with nothing to remove, and no re-seal of spec 025-identity-regen, it MUST NOT commit. When that commit fails with a store error other than `LogFull`, `outbox` MUST still return, from memory and changing nothing, what it would hand out — stale entries counted as gone for the ordering rule of spec 025-identity-regen R4 and not handed out, and a `key_retired` due for its re-seal handed out re-sealed in memory with a fresh nonce and a fresh `client_ref`, neither stored — one such copy per minute of `now`, kept in memory and handed out again for the rest of that minute, counted as in flight when its `client_ref` is in `in_flight`, and answered by `acked` with `Ignored` and its `sent_at`, so that the hold of spec 028-session-sans-io R12 applies and only a committed copy completes the retirement (spec 025-identity-regen R5) — with the error in `OutboxStep::store_error` and, in `not_delivered`, the stale entries this `Channel` instance has not reported yet (the later removal may report them again; a repeated `NotDelivered` for one `client_ref` changes nothing) (an exception to R2's return; memory is kept as R2 says), and for 600 000 ms after it attempts no commit and hands out from memory in the same way, so that a disk that cannot be written does not hold back the retirement (the echo of such a copy is harmless: step 5 never removes the `key_retired`).
- R23 `expire_outbox(now, in_flight)` MUST do the removal of R22 alone — no blob handed out, no re-seal — for a channel that is not subscribed (spec 027-core-api R12), with R22's failure behaviour: when the commit fails, it still returns, as an `OutboxStep` with `publish` empty, the stale entries this instance has not reported yet, with the error in `store_error`, and attempts no commit for 600 000 ms.

**Gaps and status**

- R24 For a consumed, not stale message from a peer that is not a `key_retired`, `Channel` MUST add to the sender's in-session gap `counter.saturating_sub(previous.saturating_add(1))`, where `previous` is the peer's `max_counter` before the message and `None` counts as no gap, and MUST set the anomalous flag when that difference is above `2^32`; `history_truncated(now)` (spec 028-session-sans-io) MUST set `truncated_at = now` (a stored `truncated_at` later than `now` is read as `now` by this requirement and R25, so a clock that was ahead neither dates the banner in the future nor keeps the gap baseline off) (state key 18 of spec 020-store-files), written with the next commit; `previous` MUST be taken as `None` for a peer whose `last_seen` is below `truncated_at − ttl_ms` when the message's `r` (R10) is at most `truncated_at + ttl_ms + 360 000`, so that messages that expired while the device was away never read as a deletion, after a lock too; a later message of such a peer counts its gap with `spans_truncation` set, so that a deletion after the truncation is still seen. `gaps()` returns the non-zero gaps and flags; they are not persisted.
- R25 `cursor()`, `synced_at()`, `status()`, `gaps()`, `config()` and `dir_name()` MUST read only memory and commit nothing; `status()` MUST return `own_key_used_elsewhere`, `read_only`, `retirement_pending` (spec 025-identity-regen), `storage_full` (the check of R18 fails now), the three values of spec 026-peer-limits, `truncated_before` (`truncated_at − ttl_ms` while `truncated_at + ttl_ms + 360 000` is not below the `now` of R1's latest timed call, or whenever `truncated_at` is set before any timed call, so that a repaint shows the truncation banner after the event is gone), and `clock_off`, which only `clock_sample(received_at, now, live)` changes — spec 028-session-sans-io R11 calls it for every `ack` and every push, `live` only for an `ack` arriving within 5 000 ms of its publish on a connection that has not tripped its 5 000 ms gap: a live sample sets the flag when `now − received_at > min(360 000, ttl_ms / 2)` (this device ahead, which a short TTL cannot absorb) or `received_at − now > 360 000` (behind), and clears it otherwise; a backlog sample sets it on `received_at − now > 360 000` and clears a flag that a backlog sample set when `received_at − now ≤ 360 000` and its `received_at` is not older than the setting one's (a backlog blob is legitimately old, never in the future) — a device-clock signal beside the per-message `sent_at` warning of `docs/spec.md` §6, which it does not replace; it comes from the server's time and not from a peer's blob; and shows why every message expires or fails when the device clock is wrong.
- R26 The `purge_at` of a message record from a peer MUST be `min(r, now) + ttl_ms`, its display expiry, with `r` of R10 and the `now` of the `decrypt` that wrote it, so that content leaves the disk when it leaves the screen; that of its seen record `max(min(r, now) + ttl_ms, sent_at + 2·ttl_ms + 360 000)` (a copy stored as late as `sent_at + ttl_ms + 360 000` is still fresh, spec 013 R12, and R10 accepts it for one more `ttl_ms`), or the first term alone when `open` read no `sent_at`, so that the seen record, and with it the step-6 checks of R9, outlives every moment a copy of a blob with a `sent_at` could still be accepted (a blob with none is bounded only by the server's `received_at`, a residual in Security); the same for an `Unreadable` (`r` as in R10, which is `received_at` when `open` read no `sent_at`) and for the record of R14, whose seen record takes `sent_at + 2·(ttl_ms + 360 000)` instead as its second term, the bound R14 accepts to; of one's own message `sent_at + 2·ttl_ms + 420 000`, the latest display expiry an in-time `ack` can give it plus the grace minute of R22, so that a failed message stays visible as failed; of an acked or not-delivered record the `purge_at` of its message; and of a kept signature `sent_at + 3·(ttl_ms + 360 000)`.

**Other**

- R27 `leave(&mut self)` MUST call `Store::destroy` (spec 020-store-files R21) and, on `Err`, return it and leave the channel usable.
- R28 `core` MUST emit no log line and MUST depend on no logging crate (`docs/spec.md` §8); the log test of spec 100-log-test runs over the server.

- R32 Every state-changing method — `create`, `encrypt`, `decrypt`, `acked`, `outbox`, `expire_outbox`, `synced`, `flush`, `probe`, `relieve_headroom`, `check_own_key`, `abandon` and `leave` — MUST have a `FailingStore` test that fails its commit (or its `destroy`) and checks that the reopened state is the one before the call.

## Limits

| Input | Range | Out of range |
| --- | --- | --- |
| `body` | valid UTF-8, the payload at most 64 511 B encoded | `BadPayload` |
| `display_name` given to `encrypt` | 0..=64 B, no Cc | `BadPayload` |
| Ordinary `outbox` entries | 0..=31 | `Store(OutboxFull)` |
| `send_counter` for an ordinary message | 0..=2^64 − 2 | `CounterExhausted` |
| Log headroom for `encrypt` and `decrypt` | `log_len + 1 114 156 ≤ 67 108 864` | `Store(LogFull)`, after a compaction only when enough has expired to restore the room (at least 1 MiB) |
| `received_at`, `now` | any u64 | saturating arithmetic; the cursor is clamped to `now` |

## Security

- R9 keeps the order of `docs/spec.md` §4: nothing reads state before the signature has proved the header (ADR 0027). The headroom check comes first but reads only the log length, which no blob can change; when it fails without a failed compaction, R19 still gives the alert (after a failed one, spec 027-core-api R14 reopens and the push comes again), and nothing else is committed and the cursor waits, so the server resends the message on the next connection (spec 028-session-sans-io).
- R10's display-expiry check: a message the server dates so that it would expire before it is shown is not consumed, and dating it earlier than its signed `sent_at` minus the margin does not shorten its life, so it cannot move `max_counter` and hide a deletion from the gap signal while never being shown.
- "Counter before blob" (§4): R7 commits `send_counter + 1` before the blob exists outside the core, so no crash can make two blobs share a counter, and so no (`mk`, nonce) pair repeats.
- The own-key alert decides by the signature this device kept, never by a counter the thief also controls (ADR 0029). R15 keeps each signature one TTL longer than any receiver accepts the blob; the `epoch` of each kept signature drops those of a retired key from the comparison in the regeneration commit, as ADR 0034 says, even after a reopen. R19 applies the same retention rule under a full log, so a replay of an old genuine blob raises no false alarm there either.
- An echo can acknowledge an entry (R13) only with the exact bytes this device published: nobody else can produce a signature this device holds, and the server already chooses `server_id` and `received_at` in an ordinary `ack`.
- A stale message moves nothing but the cursor (ADR 0027): R10 and R14.
- The cursor stays in the server's time and is clamped to the local clock (R20), so a server that sends a `received_at` in the far future cannot push it past every later message, and a device clock ahead of the server cannot skip what the server receives next, nor what it still holds (R20's exception for pushes already expired by the local clock). A cursor-only commit happens at most once a minute, which bounds what a stream of junk pushes can make the device write.
- R9's pair check stops a republished blob from being shown twice after its sender was evicted or pre-verified without a `max_counter`, for as long as any copy could be accepted, since R26 keeps the seen record that long; the body goes at its display expiry, so a flood of far-dated messages holds the log no longer than one TTL. It applies to peers only: for one's own key, a thief's blob with the counter of one of this device's messages must still reach the signature test of R13, or the race of ADR 0029 would hide the alert.
- One's own messages sent while the device clock was ahead keep that clock's `received_at` and `purge_at`: after the clock is corrected, their failed rows sort below newer ones and stay listed, and on disk, for up to the clock error longer. Documented residual.
- A device whose clock is ahead and that only reads, never sending, gets no `clock_off`: pushes are never live samples, since held and buffered pushes are legitimately late. Documented residual.
- The own-key values held only in memory (R19) — the alert, the counter bump, `read_only` and the pending removal — are lost if the disk stays unwritable through a lock and until the thief's blob leaves the server: the next unlock no longer fetches it, and messages sent then at counters the thief overtook read `Delivered` while receivers reject them. `flush` tries to persist it, and `status()` shows it while the device is unlocked. Documented residual.
- `clock_off` is advice from an untrusted server, which can set it or hide it; the client (specs 050–052, bound by 027-core-api R14) says only that the device's time differs from the server's and suggests turning on automatic time, never a time or an offset.
- The ten-minute limit on compactions holds within one unlock: the last attempt lives in memory, so a device unlocked often may try one compaction per unlock per channel on a flooded channel or a full disk, and a channel reopened by an import, a create retry or the tick's retry of a broken channel (spec 027-core-api R4, R5, R12, the last itself at most once per ten minutes) starts a new window. Documented; persisting the time would add a state write to every attempt.
- A blob with no readable `sent_at` (an `Unreadable`, or one's own key's blob sealed elsewhere) can be re-pushed by the server once its seen record lapses, as a new row for a sender with no `max_counter` (evicted, forgotten or never seen); the server cannot mint one, a config holder can mint new ones anyway, and one's own key's alert is already set. Documented residual.
- No verdict reaches the network: `decrypt` returns its `Error` to the caller only, and spec 028-session-sans-io never lets one shape a frame (§4 "No-oracle rule").
- Secrets: the identity seed and `sk_u` live only inside `ChannelState` and the `SenderKey` built from it for one `seal`; `mk` for one call. `Received` carries content and never reaches a log (R28).
- The whole log of an open channel is held in memory (R1), at most 64 MiB per channel; with the per-channel quota of the server that is the worst case, not the usual one. Documented; a lazy message list is a v1.x option if measurements ask for it.

## Public API changes

None directly: `Channel` is crate-internal, and spec 027-core-api exposes its calls through `Device`. At acceptance, `docs/spec.md` §6 gains the device-clock warning (`ChannelStatus::clock_off`, from the server's `received_at` of `ack`s and live pushes, R25) beside its per-message `sent_at` warning. ## Vectors

None of its own. `decrypt` on a fresh channel reproduces the receive vectors of `013.json` (every verdict of spec 013, and `commits = 0` for each rejection); a 013 vector whose `received_at` puts it past its display expiry is `Expired` here by R10. The stateful rejections — `Replay`, `RetiredKey`, `PeerLimit` — need state built by a sequence of calls, so they are unit tests (`specs/vectors/README.md`).

## Acceptance criterion

`cargo test -p privatechat-core s021_` green, T30 included; the fuzz target `channel_decrypt` builds and runs in the nightly workflow; clippy, `cargo deny` and the documentation lint green. Non-automatable: a second person walks R9–R15 and R19 against `docs/spec.md` §4 steps 5–8 and "Messages from one's own key".

## Out of scope

- Peers, labels and verification (spec 022-peers-tofu); the message list and the periodic purge (spec 023-ttl-purge); a received `key_retired` and `read_only` (spec 024-key-retired); regeneration and the pending `key_retired` (spec 025-identity-regen); room for unknowns, eviction and the ignored-keys count (spec 026-peer-limits).
- Frames, subscription, `auth_subscribe` and reconnection (spec 028-session-sans-io); the public calls and the 10 000-message run (spec 027-core-api).
