## Context

`docs/spec.md` §9 sketched a boundary of several handles — `Config`, `Channel`, `Session`, `Settings` — passed to each other by value. uniffi cannot express that: its objects are shared `Arc`s with `&self` methods, never moved, never borrowed out, and a `Box<dyn Store>` cannot cross at all (audit J, J-C4). ADR 0037 replaces them with one opaque handle, `Device`, which owns the vault, every channel, the settings and one `Session` per connection, and whose calls name channels and connections by id. The bindings (specs 040-uniffi, 041-desktop-bridge) wrap exactly one `Mutex<Device>`.

This spec defines `Device`: how it opens, imports, exports and lists channels, how it plans connections, how it dispatches every per-channel call of specs 021–026, how it recovers from a failing store, and which items of `core` and `store` are `pub`. After it is accepted, §9 and AGENTS 20 point here and the API does not change again before the clients (`docs/spec.md` §10).

**In plain words.** The apps talk to the core through one object that stands for "this device". Everything is asked by name: "send this in channel X", "here is a frame from connection 3". The object knows which channels exist, which server each one uses, how many connections to open, to where and through which proxy. Secrets go in once as bytes and never come back out as text; errors are plain names with nothing attached; and the core never writes a word the user reads.

## Requirements

**Opening and settings**

- R1 `Device::open(vault, now)` MUST list the stores and load the settings, and fail with `Error::Store(Io)` when `list` fails with `Io`. When `load_settings` returns `Io`, `Corrupt` or `UnsupportedVersion`, or returns `None` while `list()` returned at least one store, it MUST use the defaults of R13 in memory without saving them and set `settings_reset` in `DeviceStatus`, with `settings_reason` the error `load_settings` returned (`None` for an absent file); when it returns `None` on a device with no channel (a fresh install), it MUST use the defaults in memory, no flag, and save nothing until the first setter, `acknowledge_settings`, `create_channel` or import, which saves them — `create_channel` and the imports before `Vault::create`, returning a failed save's error with nothing created, and keeping a save that succeeded when the channel creation then fails — so that hiding the channel directories for one unlock cannot make the device write proxy-less settings on its own. It MUST then open every listed store with `Channel::open_stored`, put each that fails with `Error::Store(e)` in `DeviceStatus::broken` with its directory name and `e`, fail with any other error, run `purge_expired(now)` on every channel that opened for which `purge_due(now)` holds (spec 023-ttl-purge R5), treating a failure as R15 does, and build the connection plan of R10.
- R2 While `settings_reset` is set, `connections()` MUST return no plan and `probe_plan` MUST return `None` for any URL in the grammar (the grammar check first, the `.onion` check of R12 only once the flag is clear), so that nothing connects before the user has seen that the settings — a proxy included — were lost; `acknowledge_settings(false)` and `set_socks5_proxy` MUST save the settings, clear the flag and release the plan — except when the flag came from `UnsupportedVersion` (a newer app's `settings.bin`, `settings_reason`), where they clear `settings_reset` and release the plan without saving, `settings_reason` staying `Some(UnsupportedVersion)` for the unlock as the mark that every setter changes memory only, so that a downgrade never overwrites a newer app's settings, unless `acknowledge_settings(true)` — offered only behind a destructive confirmation ("written by a newer version of the app: update it, or replace these settings") — saves the settings in memory, clears `settings_reason`, and lets the setters save again; when the re-read after an `Io` returns `UnsupportedVersion`, `settings_reason` becomes that and the call proceeds the same way — `acknowledge_settings` and `set_socks5_proxy`, when the flag came from an `Io`, first call `load_settings` again and, when it now reads, adopt that file — `acknowledge_settings` applying onto it the setter changes made while the flag was set and saving only when there were any, `set_socks5_proxy` applying those and the proxy onto it before saving — so that a passing read error does not overwrite a stored proxy; while the flag is set, the other setters change the settings in memory only and save nothing, so that no settings file without the lost proxy is written and nothing connects before the user has decided about it. A setter or `acknowledge_settings` whose save fails MUST keep the previous settings, `settings_reset` and `settings_reason` in memory; `replace_newer` has no effect unless `settings_reason` is `Some(UnsupportedVersion)`, the call otherwise acting as `acknowledge_settings(false)`.
- R3 `remove_broken(name)` MUST remove that directory through `Vault::remove` and drop it from `broken`; a name not in `broken` MUST return `Error::UnknownChannel`, and a failing `remove` returns its error and leaves the entry in `broken`. A client offers it for `Corrupt`, and for an `Io` entry that carries a `channel_id` as an explicit "leave this channel" (so a flooded channel whose reopen failed can still free its space), and for one without behind a destructive confirmation ("could not be read: remove it and lose its local history"); and for `UnsupportedVersion` only behind an explicit destructive confirmation ("written by a newer version of the app: update it, or remove the channel and lose its local history"), since that byte is outside the box and a local writer can forge it. A successful `leave` or `remove_broken` makes the retries and probes of R12 due at the next tick, since it may have freed space.

**Channels**

- R4 `create_channel(server_url, ttl_seconds, name, now)` MUST call `Config::create` of spec 011-config-format, `Vault::create` and `Channel::create`, and return the new channel's `ChannelInfo`. When `Channel::create` of this call or of R5 returns `Error::Store(Io)`, the `Device` MUST drop that store and try `Vault::create` and `Channel::open_stored` once: when a state stands (a commit that poisoned the store after its rename, spec 020-store-files R11), it opens the channel and returns `Ok` with `is_new = true`; the retry calls `Store::load` first: `Ok(None)` means no state stands and it returns the original `Io` (spec 020-store-files R19 removes the directory at the next open); `Ok(Some)` goes on to `open_stored`; when the retry fails with a store error, it puts the directory in `broken` with that reason, the `channel_id` and the name as R14 does, and returns the original `Io`.
- R5 `import_qr(text, replace_broken, now)` and `import_file(bytes, password, replace_broken, now)` MUST parse with `Config::parse_qr` or `Config::open_encrypted`, and then: for a `channel_id` already open, return its `ChannelInfo` with `is_new = false` when the `server_url` matches and `Error::ConfigMismatch` otherwise, touching no store; for a `channel_id` whose directory (`Vault::dir_name`) is in `broken`, first retry `Channel::open_stored` on it when its reason is `Io`, and on success drop the entry from `broken` and open it as an existing channel, the `server_url` check of the first branch applying, or on failure record the retry's error as the entry's reason, with the `channel_id` and the suggested name from the parsed config, cleaned as spec 022-peers-tofu R6, so that R12 retries it from then on; then return `Error::Store(reason)` with that entry's reason, unless the reason is `Corrupt` or `UnsupportedVersion` and `replace_broken` is true (the client asks for the latter only behind the confirmation of R3), in which case remove that directory — a failing removal returns its error and keeps the entry — drop the entry from `broken` and go on; otherwise `Vault::create` and `Channel::create`, with `is_new` from spec 021-channel-session R4 and R5.
- R6 `export_qr(channel, now)` and `export_file(channel, now)` MUST call `Config::export_qr` and `Config::export_encrypted` on the channel's stored config (ADR 0028); `export_file` returns an `ExportedFile { file, password }`.
- R7 `channels()` MUST return one `ChannelInfo` per open channel, in the order the device opened or created them, with the id, `server_url`, `suggested_name`, `local_name`, `own_display_name` (the name `send` uses by default, read with `Channel::own_display_name`), `ttl_seconds`, `ChannelStatus`, `write_failed` (R14) and `needs_proxy` (R10). The names of a `ChannelInfo` are cleaned as spec 022-peers-tofu R6 says. `rename_channel(channel, name)` MUST call `Channel::set_local_name`, which commits `local_name` (state key 8 of spec 020-store-files) as 1..=`MAX_NAME` bytes with no Cc character and a non-empty key (spec 022-peers-tofu R4), or clears it for `""`, and returns `Error::BadPayload` with nothing committed otherwise.
- R8 `leave(channel)` MUST call `Channel::leave` (spec 021-channel-session R27); on `Ok` it removes the channel from the device and from its run, and on `Err` it keeps the channel and returns the error; `leave` is not a failure of R14; when `leave` of a `write_failed` channel returns `Error::Store(Io)`, the `Device` reopens it silently once, as R14 does for a failing direct writer, and retries `leave` once.
- R9 Every per-channel call of the Interface MUST find the channel by its `channel_id`, return `Error::UnknownChannel` when it is not open, and otherwise call the `Channel` method of the spec named in the Interface. `send` and `regenerate_identity` MUST then call `Session::after_send` of the channel's connection, when it has one, and return its events, `send` with the new `Message` of spec 023-ttl-purge R7 in its `Sent`, read with `Channel::message` right after `encrypt` returns `Ok` and before `after_send` (a `None` there, which only a bug can cause, returns `Error::Internal`); a `regenerate_identity` on a channel whose publishing the session stopped after an own-key alert returns the `Event::Reconnect` of spec 028-session-sans-io R10, so that the retirement can leave; once `Channel::encrypt` or `regenerate_identity` has committed, they MUST return `Ok`, but for that `Internal`, a later store failure becoming `Event::StorageFailed` on a channel that is not `write_failed` (R14); when the commit itself poisoned the store after its rename (spec 020-store-files R11), the `Device` reports what the reopened state shows: for `send`, it reads `send_counter()` before `encrypt` and returns `Ok(Sent)` when `outbox_ref` of that counter is there after the reopen (spec 021-channel-session R33); for `regenerate_identity`, `Ok` when the retirement is pending. Every other direct writer returns its error, and the client repaints the channel as R14 says.

**Connections**

- R10 `connections()` MUST return the plan. Without a proxy, a channel whose host, with its trailing dots removed, ends in `.onion` is in no run and shows `ChannelInfo::needs_proxy`, so that no resolver is ever asked for a hidden service; the other open channels are grouped by the scheme, host and port of their `server_url` (ADR 0038); each group is a list of runs of at most 16 channels; a new channel joins the last run of its group with room, or starts a new run; a channel that leaves is removed from its run and no other run changes, and a run left with no channel is removed from the plan. With a SOCKS5 proxy set, each channel is its own run. Each run is one `ConnectionPlan`, and its route is the host, the port, `tls` (false only for a `ws://` URL, which spec 011-config-format R5 allows only for an onion host; such a channel is in a run only while the SOCKS5 proxy's host is a loopback IP literal, in `127.0.0.0/8` or `::1` (never a host name, `localhost` included, which would trust a resolver), and otherwise is in no run and shows `needs_proxy`, so that plain WebSocket never crosses a network to reach the proxy; `needs_proxy` therefore means "this channel needs a SOCKS5 proxy running on this device", and the client says it in those words), the proxy and, with a proxy, a `socks_username` of 8 lowercase hex characters drawn with `random_bytes` when the plan's `id` is minted, so that no observer of the proxy protocol learns the `channel_id` or links a channel across plans. A plan keeps its `id` and its username while its channels and its route are unchanged; any other plan gets an `id` this `Device` never used.
- R11 After `open` and after every call that takes `&mut self` other than `outgoing` and `on_disconnect`, the client MUST reconcile its sockets with `connections()` — open a socket for each new `id` along its route, close each socket whose `id` is gone — and then drain `outgoing()` of every connected plan. Every socket that closes, whoever closed it, is reported with `on_disconnect`; one the peer or the network closed is reopened with backoff while its `id` is in the plan; after `Event::UnsupportedServer` the client closes that socket and does not reopen it until the next `open` or a new plan `id`; after `Event::Reconnect` it closes it and reopens it with backoff. `connections()` MUST leave out a plan whose channels have all been refused since it was built. `on_connect`, `on_frame`, `outgoing` and `on_disconnect` MUST route to that connection's `Session` of spec 028-session-sans-io, passing to `on_connect` the channels refused by `SubscribeRefused` since the plan was built; an `id` not in the plan MUST be ignored, with no event and no frame.
- R12 `on_tick(now)` MUST call `Session::on_tick` of every connected session, call `Channel::expire_outbox` (spec 021-channel-session R23) for every channel whose connection is not connected, treating a `store_error` it returns as R14 treats a store failure, and produce `Event::NotDelivered` for each entry it removes (a connected session does the same for its own unsubscribed channels, spec 028-session-sans-io R14), run `purge_expired(now)` on a channel for which `purge_due(now)` holds (spec 023-ttl-purge R5) — at most one compaction (purge or relief) and one reopen (probe or `broken` retry) per `on_tick`, the other due channels waiting for later ticks, so that a tick stays well under the 5 000 ms gap of spec 028-session-sans-io R9 — call `relieve_headroom(now)` (spec 021-channel-session R18) for a channel whose `status().storage_full` is set, within the same one-compaction-per-tick budget, probe every `write_failed` channel at its probe time (one more than 600 000 ms after `now`, after a clock set back, counting as due): reopen it silently as R14 does and call `Channel::probe(now)` (spec 021-channel-session R20); on success clear the mark with `set_write_failed(channel, false, storage_full)`, `StatusChanged` and, when its connection is connected and `status().storage_full` is not set, `Event::Reconnect`, so that the pushes it held are fetched again (with `storage_full` set, the channel returns to the `LogFull` stall of spec 028-session-sans-io R10, whose own `Reconnect` comes when room returns), and on failure set its probe time 600 000 ms ahead with no event; a `send` that returns `Ok` on a marked channel makes its probe due at the next tick, unless its last clearing was less than 600 000 ms ago (a clearing recorded later than `now` counting as older) (a state-only writer proves nothing about room for a message); retry, once every 600 000 ms since it was recorded (a later time counting as passed), every `broken` entry whose reason is `Io` and that carries a `channel_id` (moved there by R4, R5 or a failed reopen of R14) with `Vault::create` and `Channel::open_stored` — an `Io` entry from `open` has no `channel_id` and is retried by the next `open` or an import of its channel (R5) — on success the channel leaves `broken`, joins a run by R10 and `StatusChanged` follows, and on failure the entry's reason and time are updated — so that a channel broken by a full disk comes back once space is freed, produce `Event::StatusChanged` for every channel whose `status()` it changed, and return, with its own events, those queued by R14; the client MUST call it at least once every 1 000 ms while unlocked. `probe_plan(server_url)` MUST return `Error::BadConfig` for a URL outside the grammar of spec 011-config-format R5, with a `.onion` host (trailing dots removed) while no proxy is set, or with the `ws://` scheme while the proxy is not a loopback IP literal (R10), and otherwise the route for the create-time check of `docs/spec.md` §5 — host, port and `tls`, and with a proxy set a `socks_username` drawn with `random_bytes` — and `probe_hello(frame)` MUST apply the version rule of spec 028-session-sans-io R2 to a `hello` and return `Error::BadPayload` for any other frame; the client closes the probe socket after its first frame, or after 30 000 ms without one, the probe then counting as failed, and it is never a planned connection.

**Settings**

- R13 The default settings MUST be `default_server_url = DEFAULT_SERVER_URL` (spec 000-repo-layout), `lock_timeout_seconds = 60` and no proxy; `set_default_server_url`, `set_lock_timeout_seconds` and `set_socks5_proxy` MUST apply the grammars and ranges of spec 020-store-files, return `Error::BadConfig` and save nothing otherwise, and save through `Vault::save_settings`.

**Store failures**

- R14 When a channel call returns `Error::Store(Io)` or `Error::Store(Corrupt)` — directly, or in the `failed` list of a `Session` step — and the channel is not `write_failed`, the `Device` MUST drop its store, reopen it with `Vault::create` and `Channel::open_stored`, carrying the channel's `last_compaction()` and, when the reopened channel has the same own `pk_u` (`own_pk()`, compared with `ct_eq`), the dropped channel's `held_own_key()`, and its in-session gaps, ignored-keys set and `clock_off`, into the reopened `Channel` (`set_last_compaction`, `hold_own_key`, `session_carry` read before the drop and `carry_session` after, spec 021-channel-session), mark it `write_failed` with a probe time 60 000 ms ahead (times measured, for the calls that take no `now`, with the `now` of the last call that carried one), or 600 000 ms ahead when its last clearing was less than 600 000 ms ago (a clearing recorded later than `now` counting as older) (so that a disk with room for the state but not for a message does not probe every minute), call `Session::set_write_failed(channel, true, false)` on its current session, and produce `Event::StorageFailed { channel }` — in the result of the `on_frame` or `on_tick` that met the failure, in that of `send` or `regenerate_identity` when it returns `Ok`, and otherwise queued for the next `on_tick` — and no `Reconnect`. A `write_failed` channel stays in `channels()` with `ChannelInfo::write_failed` set, answers every read call and `leave` (so the user can still read its history and free its space), and stays in its run, its session holding it in the receive-only stall of spec 028-session-sans-io R10 (every push to `check_own_key`, so the own-key alert still arrives, and the `outbox`, the pending `key_retired` included, still handed out from memory by spec 021-channel-session R22); while it is marked, the tick runs no `purge_expired` or `relieve_headroom` on it (its `expire_outbox` reports stale entries from memory, spec 021-channel-session R23), a failure from its session or the tick reopens nothing and produces no event, and a failing direct writer reopens it once, carrying the same values, with no event, so that R9's outcome rule reads what stands. R12 probes it and clears the mark. The `Device` calls `set_write_failed(channel, true, false)` for each marked channel whenever it builds a `Session`. When a reopen fails, from any path, the channel MUST move to `broken`, with `Event::StorageFailed { channel }` in the step's result or queued for the next `on_tick`, with its error, its `channel_id` and its `local_name` when set, else its `suggested_name`, cleaned as spec 022-peers-tofu R6 and taken before the `Channel` is dropped, and leave its run. `OutboxFull` and `LogFull` are returned as they are and reopen nothing. A direct call still returns its error, except as R9 says. Around every direct per-channel writer (`send`, `label`, `verify`, `verify_scanned`, `mute`, `retire`, `forget`, `regenerate_identity`, `purge_expired`), the `Device` MUST compare `status()` before and after and call `take_peers_changed()`, and on a change return `Event::StatusChanged` for that channel with the call's events, or queue it for the next `on_tick` when the call returns none; `on_tick` MUST also call `take_peers_changed()` and drain `take_outcomes()` (as `Event::NotDelivered`) for every channel with no connected session, as after `probe`, `flush` and every direct writer, and produce `Event::StatusChanged` for each that returns `true`. After `StatusChanged` for a channel it does not list or whose `write_failed` it shows, after every successful import, and after every settings setter or `acknowledge_settings` that returns `Ok` (the proxy decides `needs_proxy`), the client re-reads `channels()` and `status()`; otherwise it marks the channel for a re-read of its `channel_status`, `peers`, `messages` and `gaps` and does it at most once a second, at its tick (specs 050–052), so that a backlog whose every push raises the event costs one re-read per second, not one per push (a peer record that vanished leaves its rows to `Message::stranger`); new messages otherwise arrive in their own events, `ChannelStatus::clock_off` is shown only as "this device's time differs from the server's; turn on automatic time", never as a time or an offset, and `Peer::last_seen` is current only as of the last re-read, not a live display. After `StorageFailed`, and after a direct call that returned `Error::Store`, the client re-reads `channels()`, `status()` and the channel's `messages`, `peers`, `channel_status` and `gaps`, since the reopened state may hold a commit whose call returned an error.
- R15 A `purge_expired` or `relieve_headroom` that fails, during `open`, from `on_tick` or called directly, MUST NOT fail `open` and MUST be handled by R14, `purge_due` and spec 021-channel-session R18 holding off the next attempt for ten minutes.

**The boundary**

- R16 The `pub` items of `core` and `store` MUST be those of the Interface; `crates/core/tests/api_surface.rs` and `crates/store/tests/api_surface.rs` MUST coerce each `pub` function to a function pointer of its exact type, so that a changed or missing signature fails to compile; `[workspace.lints.rust]` MUST set `unreachable_pub = "deny"`, and `server` uses `pub(crate)` throughout except the entry points of its `lib.rs` that spec 035-server-ops R10 names (`bind`, `Bound`, `Settings`, `ConfigError`, `StartError`, `StartReason`, `DbCause`, `Outcome`, `Clock`, `SystemClock`, `log::init`, and `ManualClock` under `test-support`). An added `pub` item that is reachable is caught in review.
- R17 This spec MUST amend spec 011-config-format so that `Config` and its functions are `pub(crate)`; amend spec 016-fuzz-harness R6 so that the reach check matches `pub(\(crate\))? fn (parse|decrypt|open|decode)\w*\(` with `&('\w+ )?\[u8\]` in its signature; gate every item that no production path calls with the cfg of its callers (`test`, `fuzzing` or `feature = "test-support"`); and remove the `dead_code` allows of `mod crypto`, `mod proto`, `mod storage` and `mod session`.
- R18 `core::Error` MUST be exactly `BadLength, UnsupportedVersion, WrongChannel, Expired, RetiredKey, PeerLimit, Replay, BadSignature, BadPayload, CounterExhausted, BadConfig, BadPassword, InviteExpired, ConfigMismatch, UnknownPeer, UnknownChannel, LabelInUse, OwnKey, RetirementPending, Internal, Store(StoreError)`, with unit variants but the last, and no `Display`: the core produces no user-facing text (`docs/spec.md` §12).
- R19 The storage key MUST enter through `StorageKey::from_bytes(&mut [u8; 32])` alone, which zeroes the caller's array; the `.chatcfg` password MUST enter as `&[u8]`; the QR text MUST cross in both directions as bytes (ADR 0028); no `pub` function MUST take or return a key, a seed or a password as `String` or `&str`.
- R20 `Device` MUST be `Send` and implement neither `Clone`, `Debug` nor `Display`; `core::init()` MUST initialise libsodium once and every other function MUST work whether or not it was called (spec 010-primitives-wrapper R2).
- R21 `create_channel`, `import_qr`, `import_file`, `remove_broken`, `rename_channel`, the settings setters, `acknowledge_settings` and `leave` MUST each have a failing-store or failing-vault test that checks the state after reopening.
- R22 In the pull request that marks this spec `accepted`, `docs/spec.md` §5 ("sends nothing to the server until the user opens the channel" becomes "until the channel is imported"), §6 (the SOCKS username of "Connections" becomes the random per-plan value of R10), §9, AGENTS 20 (`Device` the only handle) and AGENTS 23 (`compact` the one other writer of `state.bin`), and the rust skill (SKILL.md and `references/patterns.md` §3–§4) MUST be brought up to date with this spec.
- R23 A test in `crates/store/src/tests/phase2_exit.rs` MUST run two `Device`s, each over a `FailingVault` of spec 020-store-files wrapping a `DataDir` on disk in fast mode, with one shared channel, against `testing::MemoryServer` of spec 028-session-sans-io, and exchange 10 000 messages, 5 000 from each device at one send every 3 000 ms of simulated time with ticks every 1 000 ms, in a channel whose TTL exceeds the queueing delay, with 1 % of the pushes duplicated and one random commit failed on each side, the random choices drawn by a proptest of one case with `max_shrink_iters = 0` (`proptest` becomes a dev-dependency of `store`, justified in the PR, AGENTS 8); it MUST end with 0 errors other than the injected ones, every message delivered once, every duplicate rejected, each reopened state equal under `state_eq` to `Faults::last_committed`, and one compaction run and checked. A second run, as a child process killed at `after_append:<k>` for a seeded *k* (spec 020-store-files "Crash points"), MUST reopen both directories without `Corrupt`, with the log length equal to `log_committed_len`, and resume the exchange with a fresh `MemoryServer`. Their duration on the CI runner is recorded in the pull request (`docs/spec.md` §10, phase 2 exit criterion).
- R24 `flush(now)` MUST call `Channel::flush` (spec 021-channel-session R20) on every channel, attempting each even after one fails, reopening nothing, and returning the first error after the last, and the client MUST call it when the app locks, before it drops the `Device`, so that a quiet channel's `synced_at` and cursor survive the lock.

## Limits

| Input | Range | Out of range |
| --- | --- | --- |
| `channel` | the `channel_id` of an open channel | `UnknownChannel` |
| `connection` | an `id` of the current plan | ignored |
| `local_name` | `""` (clears), or 1..=64 B UTF-8, no Cc, a non-empty `name_key` | `BadPayload` |
| Channels per connection | 1..=16; 1 with a proxy | a new run |
| Wait for the probe's first frame | ≤ 30 000 ms, a client-side rule tested by specs 050–052 | the probe fails (the client closes the socket) |
| Compactions and reopens per `on_tick` | at most one of each (R12) | the rest wait for later ticks |
| `on_tick` period | ≤ 1 000 ms while unlocked | subscribes miss their window (spec 028 R7); a gap over 5 000 ms reconnects (spec 028 R9) |
| Reopens with `StorageFailed` per channel (R14) | one, then `write_failed` until a probe commit succeeds (R12: after 60 000 ms, or 600 000 ms when the last clearing was less than 600 000 ms before, then every 600 000 ms); silent reopens at each probe and at each failing direct writer while marked | stalled receive-only while marked |

Every other limit is that of the spec each call comes from.

// core — the handle
pub struct Device { /* the Vault, the open channels, the broken names, the settings, the plan, one Session per connection */ }

pub struct DeviceStatus { pub settings_reset: bool, pub settings_reason: Option<StoreError>, pub broken: Vec<BrokenChannel> }   // R1, R2

## Security

- One handle means one place a reviewer reads to know what the clients can do (R16), and no secret-holding object ever crosses by value: `Config`, `Channel`, `Session` and the stores stay inside Rust.
- The plan puts at most 16 channels on one connection and, behind a proxy, one channel per circuit; the SOCKS username is random per plan (R10), so a network observer of a remote proxy learns neither the `channel_id` nor that two users share a channel, and cannot link one channel across plans; any change of route reopens the connection, so turning a proxy on never leaves a direct socket open.
- A lost settings file connects nothing until the user has seen it (R2), so deleting `settings.bin` cannot silently drop a Tor proxy on a device that holds channels. On a device with no channel it is indistinguishable from a fresh install, and the defaults are saved only by the user's first write; the user who set a proxy and then left every channel must set it again — a documented residual. Rolling `settings.bin` back to an older version is not detected, like the rollback of a channel (spec 020-store-files, Security), and is documented.
- Errors carry no data (R18), so none can leak content, a key or a path into a client log.

## Public API changes

This spec is the public API. Against `docs/spec.md` §9: one handle, `Device`, in place of `Config`, `Channel`, `Session` and `Settings`; every call by `channel_id` or connection `id`; import, export, listing and settings through `Device`; `probe_plan` and `probe_hello` for the create-time check; `encrypt` becomes `send` and returns a `Sent`; `messages`, `verify_scanned`, `forget`, `own_old_keys`, `rename_channel`, `remove_broken`, `acknowledge_settings`, `connections` and `Event` are new; five `Error` variants are new. AGENTS 20 lists `Device` as the only opaque handle.
