## Context

The Definition of done in `docs/spec.md` §10 is only worth anything if a machine checks it on every change. The phase 0 CI enforces formatting, lints, tests, dependencies, documentation consistency and requirement→test traceability; in addition it protects the wire format by demanding an ADR when sensitive paths are touched (AGENTS 3) and the commit format (AGENTS 7). Later phases add fuzzing, integration and reproducible builds (§10 "CI per phase").

## Requirements

- R1 `cargo fmt --all --check` MUST run and fail on any formatting difference.
- R2 `cargo clippy --all-targets --all-features -- -D warnings` MUST run; any warning is an error.
- R3 `cargo deny --all-features check -D checksum-mismatch` (advisories, bans, licenses, sources) MUST run with `deny.toml`; `-D checksum-mismatch` raises a pinned build script that no longer matches from a warning to a failure (spec 010 R16).
- R4 `scripts/doc_lint.sh` MUST run with `DOC_LINT_BASE` = base commit of the PR when there is one.
- R5 Runs on the same branch MUST cancel the previous one (`concurrency` with `cancel-in-progress`).
- R6 The Rust jobs MUST use a `cargo` cache so that dependencies are not recompiled on every run.
- R7 `scripts/check_requirements.sh` MUST run and fail if an `R*` of an implemented spec has no `sNNN_tTT_rRR_*`; an `accepted` spec is not yet gated, because its tests are written after acceptance. It MUST first run itself on fixtures that each break one of its rules, and fail if any of them passes.
- R8 On every PR, a diff that touches `crates/core/src/{proto,crypto,storage}.rs` or anything under those three modules, `crates/store/src/**` and `crates/store/tests/golden/**` (the file framing of spec 020 and its frozen files), `specs/vectors/**` or `specs/011-*`, `012-*`, `013-*`, `014-*`, `017-*`, `020-*`, `031-*` — a renamed file counted at both its old and its new path — without adding a `docs/adr/NNNN-<kebab>.md` file whose number the base does not have MUST fail, unless the PR carries the `adr-not-needed` label.
- R9 On every PR, every non-merge commit MUST have a subject that starts with `NNN: `, `docs: `, `ci: `, `chore: ` or `adr: `; an empty subject fails, and so does a base the log cannot reach.
- R10 The CI MUST run on `push` to `main` and `mvp` and on every `pull_request`, again when its labels or its base change, with read-only permissions, every step in `bash` with `-eo pipefail`. `mvp` MUST take changes only through a pull request whose jobs are green (branch protection), so that R8 and R9 see every change.

## Limits

- The CI uses the toolchain pinned by `rust-toolchain.toml`.
- No secrets in the phase 0 CI: there is no deployment and no signing.

## Interface

File `.github/workflows/ci.yml` with the jobs `fmt`, `clippy`, `test`, `deny`, `doc-lint`, `check-requirements`, `adr-guard`, `commit-lint`; later specs add jobs of their own (`store-macos`, spec 020-store-files R23). Every step that covers a requirement carries the id `sNNN_tTT_rRR_*` as its `name`, so that `check_requirements` finds it.

## Security

- `permissions: contents: read, pull-requests: read`. No token with write access.
- Third-party actions pinned to a major version (`@v7`, `@v2`); Dependabot updates them.
- `adr-guard` is the mechanical barrier against silent changes to the wire format.
