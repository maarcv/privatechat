## Context

La Definició de fet de `docs/spec.md` §10 només val si una màquina la comprova a cada canvi. La CI de la fase 0 fa complir el format, els lints, els tests, les dependències, la coherència documental i la traçabilitat requisit→test; a més protegeix el format de cable exigint una ADR quan es toquen camins sensibles (AGENTS 3) i el format dels commits (AGENTS 7). Les fases posteriors hi afegeixen fuzz, integració i builds reproduïbles (§10 «CI per fase»).

## Requisits

- R1 `cargo fmt --all --check` MUST executar-se i fallar amb qualsevol diferència de format.
- R2 `cargo clippy --all-targets --all-features -- -D warnings` MUST executar-se; qualsevol warning és un error.
- R3 `cargo deny check` (advisories, bans, licenses, sources) MUST executar-se amb `deny.toml`.
- R4 `scripts/doc_lint.sh` MUST executar-se amb `DOC_LINT_BASE` = commit base de la PR quan n'hi ha.
- R5 Les execucions d'una mateixa branca MUST cancel·lar l'anterior (`concurrency` amb `cancel-in-progress`).
- R6 Els jobs de Rust MUST usar cache de `cargo` per no recompilar dependències a cada execució.
- R7 `scripts/check_requirements.sh` MUST executar-se i fallar si un `R*` d'una spec acceptada no té cap `sNNN_tTT_rRR_*`.
- R8 A cada PR, un diff que toqui `core/src/proto/**`, `core/src/crypto/**`, `specs/vectors/**` o `specs/011-*`, `012-*`, `013-*` sense afegir cap fitxer `docs/adr/NNNN-*.md` MUST fallar, llevat que la PR porti l'etiqueta `adr-not-needed`.
- R9 A cada PR, tot commit que no sigui de merge MUST tenir un assumpte que comenci per `NNN: `, `docs: `, `ci: `, `chore: ` o `adr: `.
- R10 La CI MUST córrer a `push` a `main` i `mvp` i a tota `pull_request`, amb permisos de només lectura.

## Límits

- Toolchain fixada a la mateixa versió que `rust-toolchain.toml` (`1.98.1`).
- Cap secret a la CI de la fase 0: no hi ha desplegament ni signatura.

## Interfície

Fitxer `.github/workflows/ci.yml` amb els jobs `fmt`, `clippy`, `test`, `deny`, `doc-lint`, `check-requirements`, `adr-guard`, `commit-lint`. Cada pas que cobreix un requisit porta l'id `sNNN_tTT_rRR_*` com a `name`, de manera que `check_requirements` el troba.
