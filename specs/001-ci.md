## Context

The Definition of done in `docs/spec.md` §10 is only worth anything if a machine checks it on every change. The phase 0 CI enforces formatting, lints, tests, dependencies, documentation consistency and requirement→test traceability; in addition it protects the wire format by demanding an ADR when sensitive paths are touched (AGENTS 3) and the commit format (AGENTS 7). Later phases add fuzzing, integration and reproducible builds (§10 "CI per phase").

## Requirements

- R1 `cargo fmt --all --check` MUST run and fail on any formatting difference.
- R2 `cargo clippy --all-targets --all-features -- -D warnings` MUST run; any warning is an error.
- R3 `cargo deny check` (advisories, bans, licenses, sources) MUST run with `deny.toml`.
- R4 `scripts/doc_lint.sh` MUST run with `DOC_LINT_BASE` = base commit of the PR when there is one.
- R5 Runs on the same branch MUST cancel the previous one (`concurrency` with `cancel-in-progress`).
- R6 The Rust jobs MUST use a `cargo` cache so that dependencies are not recompiled on every run.
- R7 `scripts/check_requirements.sh` MUST run and fail if an `R*` of an implemented spec has no `sNNN_tTT_rRR_*`; an `accepted` spec is not yet gated, because its tests are written after acceptance.
- R8 On every PR, a diff that touches `crates/core/src/proto/**`, `crates/core/src/crypto/**`, `specs/vectors/**` or `specs/011-*`, `012-*`, `013-*` without adding a `docs/adr/NNNN-*.md` file MUST fail, unless the PR carries the `adr-not-needed` label.
- R9 On every PR, every non-merge commit MUST have a subject that starts with `NNN: `, `docs: `, `ci: `, `chore: ` or `adr: `.
- R10 The CI MUST run on `push` to `main` and `mvp` and on every `pull_request`, with read-only permissions.

## Limits

- The CI uses the toolchain pinned by `rust-toolchain.toml`.
- No secrets in the phase 0 CI: there is no deployment and no signing.

## Interface

File `.github/workflows/ci.yml` with the jobs `fmt`, `clippy`, `test`, `deny`, `doc-lint`, `check-requirements`, `adr-guard`, `commit-lint`. Every step that covers a requirement carries the id `sNNN_tTT_rRR_*` as its `name`, so that `check_requirements` finds it.

## Security

- `permissions: contents: read, pull-requests: read`. No token with write access.
- Third-party actions pinned to a major version (`@v4`, `@v2`); Dependabot updates them.
- `adr-guard` is the mechanical barrier against silent changes to the wire format.
