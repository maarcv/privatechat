# ADR 0026 — Invitation with a fixed expiry, a text QR and a canonical password

Date: 2026-09-24 · Status: superseded by 0028

## Context
Audit E found three places where the invitation of `docs/spec.md` §5 left interoperability or simplicity open:

- **The file password (E-B4, E-A15, E-C12).** The 7 words are generated, shown on one device and typed on another, but neither the bytes fed to Argon2id nor who generates them were fixed. If one client joined the words with spaces and another with hyphens, every cross-platform import would fail as a wrong password. And "the UI generates it" put a secret and a random source outside `core` and libsodium (AGENTS 2, 20).
- **The expiry (E-A17, E-C17).** It was an optional parameter with a default of 10 minutes for the QR and 24 hours for the file, and a maximum of 24 hours. That meant two range checks, a `None` that meant "never", and a stored config that could stop loading once its invitation date had passed (E-C11).
- **The QR (E-C26).** The QR carried the config as raw binary. iOS and Android scanner APIs hand back text by default, and reading raw bytes needs a different API on each platform.

## Decision
`core` generates the file password: 7 words, each drawn as 11 bits from `randombytes_buf` over the English BIP-39 list. Its canonical bytes are the lowercase ASCII words joined by a single U+0020. When a file is opened, the password is canonicalised before Argon2id: ASCII letters are lowercased, runs of whitespace become one U+0020, and leading and trailing whitespace is removed. The invitation expiry is fixed, with no parameter: `now + 600 000` ms for the QR and `now + 86 400 000` ms for the file. It is dropped from the config once the config is imported. The config QR is the base64url text, without padding, of the config record, with no prefix and no URL scheme.

## Alternatives considered
- Password generated by each client: three random sources and three encodings of one secret.
- Accepting the typed password byte for byte: a stray space or a capital letter from the keyboard is indistinguishable from a wrong password.
- A configurable expiry: two checks and a test for a setting nobody asked for, and "no expiry" contradicted the 10-minute default.
- A raw binary QR: smaller by a third, but each platform would need its own raw-byte scanner.

## Consequences
- A file exported on one platform opens on every other, whatever keyboard typed the words.
- The password stays at 77 bits (2 048 = 2^11, so the draw has no bias). The longest possible password is 62 bytes.
- `Config::export_qr` and `Config::export_encrypted` take `now` and no expiry. A config reloaded from `state.bin` never carries `invite_expires_at`, so it cannot expire after import.
- The config QR is about a third larger. A config is at most 512 bytes, so the QR text is at most 683 characters, which still fits a QR code comfortably.
- Affected specs: 011-config-format, 021-channel-session, 027-core-api, 054-qr-invite.
